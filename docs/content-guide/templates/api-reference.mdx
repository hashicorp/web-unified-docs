## Create a resource

One short paragraph describing what the endpoint does. Where the endpoint has
notable behavior — it is idempotent, it returns before the work completes, it
fails when the target already exists — say so here.

| Method | Path                        |
|:-------|:----------------------------|
| `POST` | `/:mount-path/resource`     |

  Keep the capability, consistency, or permission table your product uses after

### Parameters

- `mount-path` `(string: <required>)` - What it identifies. This is specified as
  part of the URL.

- `name` `(string: <required>)` - What it sets. What the accepted values are.

- `optional_setting` `(int: 0)` - What it configures. What happens when it is
  omitted or set to the default.

### Sample payload

```json
{
  "name": "example",
  "optional_setting": 10
}
```

### Sample request

```shell-session
$ curl \
    --header "AUTH_HEADER: $TOKEN" \
    --request POST \
    --data @payload.json \
    $ADDR/v1/mount-path/resource
```

## Read a resource

One short paragraph describing what the endpoint returns.

| Method | Path                          |
|:-------|:------------------------------|
| `GET`  | `/:mount-path/resource/:name` |

### Parameters

- `mount-path` `(string: <required>)` - What it identifies. This is specified as
  part of the URL.

- `name` `(string: <required>)` - Which resource to read. This is specified as
  part of the URL.

### Sample request

```shell-session
$ curl \
    --header "AUTH_HEADER: $TOKEN" \
    $ADDR/v1/mount-path/resource/example
```

### Sample response

```json
{
  "data": {
    "name": "example",
    "optional_setting": 10
  }
}
```
