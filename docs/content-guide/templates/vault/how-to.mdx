# Achieve a specific outcome

One or two sentences naming the outcome and the components involved. Link the
key concepts rather than explaining them here.

## Before you start

Vault how-to pages open with **Before you start**, not Requirements or
Prerequisites. Write each item as a bolded imperative or condition, followed by
the detail that makes it actionable:

- **Read about [some concept](/vault/docs/concepts/example)**. Say why the reader
  needs it before starting.

- **Install [some tool](https://example.com)**. Say what the reader does with it.

- **Check your permissions**. You must have permission to:
  - `<do the first thing>`
  - `<do the second thing>`

- **Optional: `<some optional setup>`**. Say what changes if the reader skips it.

## Step 1: Do the first thing

Each step in the procedure gets its own H2, numbered, with an imperative heading.
Introduce the step when the heading does not fully explain it, then give the
ordered actions:

1. `<First action.>` Link the [reference documentation](link) for any command or
   parameter the step uses:

   ```shell-session
   $ vault <command> <argument>
   ```

1. `<Second action.>` Put explanation for a step inside that step, as a new
   paragraph or a nested list:

   ```shell-session
   $ vault <command> <argument>

   <real output, pasted verbatim from a run>
   ```

A step that is a single action does not need an ordered list. Write it as prose
with the command below it.

## Step 2: Do the second thing

Use a `<CodeBlockConfig>` with `highlight` to draw attention to the lines that
matter in a long configuration file:

<CodeBlockConfig highlight="2,5-7">

```hcl
setting_one = true
setting_two = "<value_to_notice>"
```

</CodeBlockConfig>

For example:

```hcl
setting_one = true
setting_two = "a-real-value"
```

## Step 3: Verify the result

End the procedure with a step that confirms the outcome. Where the reader can
verify through more than one interface, use tabs:

<Tabs>

<Tab heading="CLI" group="cli">

```shell-session

<real output>
```

</Tab>

<Tab heading="API" group="api">

```shell-session
   ${VAULT_ADDR}/v1/<path>
```

</Tab>

</Tabs>

## Additional resources

Vault uses **Additional resources** and **Next steps** in roughly equal measure.
Use **Next steps** when linking to the task the reader does next, and
**Additional resources** when linking to reference and concept material. Keep
whichever fits and delete the other.
