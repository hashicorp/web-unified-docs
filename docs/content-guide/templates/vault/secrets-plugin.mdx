## Setup

Most secrets engines must be configured in advance before they can perform their
functions. These steps are usually completed by an operator or configuration
management tool.

1. Enable the Name secrets engine:

    ```shell-session
    $ vault secrets enable name
    Success! Enabled the name secrets engine at: name/
    ```

    By default, the secrets engine mounts at the name of the engine. To enable
    the secrets engine at a different path, use the `-path` argument.

1. Configure Vault to connect and authenticate to `<the external system>`:

    ```shell-session
    $ vault write name/config/access \
        address="127.0.0.1:8500"
    Success! Data written to: name/config/access
    ```

1. Configure a role that maps a name in Vault to `<what it maps to>`:

    ```shell-session
    $ vault write name/roles/my-role \
        policy="<policy>"
    Success! Data written to: name/roles/my-role
    ```

## Usage

After the secrets engine is configured and a user or machine has a Vault token
with the proper permissions, it can generate credentials.

1. Generate a new credential by reading from the `/creds` endpoint with the name
   of the role:

    ```shell-session
    $ vault read name/creds/my-role

    Key                Value
    ---                -----
    lease_id           name/creds/my-role/<lease_id>
    lease_duration     768h
    lease_renewable    true
    token              <generated_credential>
    ```
