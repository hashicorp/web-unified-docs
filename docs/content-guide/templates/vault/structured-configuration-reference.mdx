## `block_name` parameters

Vault names its parameter block after the stanza it documents — `` ## `raft`
parameters ``, `` ## `azure` parameters `` — rather than using the global
template's Configuration model, Complete configuration, and Specification
headings.

List required parameters first in alphabetical order, then optional parameters in
alphabetical order:

- `parameter_name` `(string: <required>)` - `<What it configures.>` `<Accepted
  values.>` `<Where the value comes from when it is not set here, such as an
  environment variable.>`

- `optional_parameter` `(int: 0)` - `<What it configures.>` `<What Vault does
  when it is omitted.>`

### `sub_block` stanza

Use an H3 named after a nested stanza when the block contains one, and list its
parameters the same way:

- `parameter_name` `(string: "")` - `<What it configures.>`
