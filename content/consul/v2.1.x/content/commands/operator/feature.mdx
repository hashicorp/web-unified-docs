# Consul Operator Feature

Command: `consul operator feature`

The `feature` subcommand of `operator` provides tools for inspecting and
changing a datacenter's feature gates. Feature gates let you enable experimental
Consul functionality for an entire datacenter without restarting agents. For
conceptual information, refer to [Feature gates](/consul/docs/manage/feature-gates).

```text
Usage: consul operator feature <subcommand> [options]

  Inspect or update cluster-wide feature gates. A token with operator
  privileges is required when ACLs are enabled.

Subcommands:
    get     Get a cluster feature gate
    list    List cluster feature gates
    set     Set a cluster feature gate
```

For more information, examples, and usage about a subcommand, click on the name
of the subcommand in the sidebar or one of the links below:

- [get](#get)
- [list](#list)
- [set](#set)

## list

Corresponding HTTP API Endpoint: [\[GET\] /v1/operator/features](/consul/api-docs/operator/feature#list-feature-gates)

This command lists every feature gate that the Consul servers in the datacenter
register, along with its desired and effective state.

The table below shows this command's [required ACLs](/consul/api-docs/api-structure#authentication).
Configuration of [blocking queries](/consul/api-docs/features/blocking) and
[agent caching](/consul/api-docs/features/caching) are not supported from
commands, but may be from the corresponding HTTP endpoint.

| ACL Required    |
| --------------- |
| `operator:read` |

Usage: `consul operator feature list [options]`

The output looks like this:

```shell-session hideClipboard
$ consul operator feature list
Name                          Stage         Desired  Effective  Eligible  Source            Reason            Min Version  Policy Index  Status Index
api-gateway-upstream-routing  experimental  false    false      true      registry-default  default-disabled  2.1.0        24            24
consul-ai                     experimental  false    false      true      registry-default  default-disabled  2.1.0        24            24
localized-dns                 experimental  false    false      true      registry-default  default-disabled  2.1.0        24            24
peering-multiport-upstreams   experimental  true     true       true      operator          operator-enabled  2.1.0        24            24
```

If the leader has not yet committed the first feature gate policy, the command
prints a warning and no gates. This situation occurs on a new datacenter or
immediately after you upgrade the servers. Wait several seconds and run the
command again.

#### Command Options

- `-format={pretty|json}` - Command output format. The default value is
  `pretty`.

## get

Corresponding HTTP API Endpoint: [\[GET\] /v1/operator/feature/:name](/consul/api-docs/operator/feature#read-a-feature-gate)

This command displays the desired state, eligibility, and effective state of one
feature gate.

The table below shows this command's [required ACLs](/consul/api-docs/api-structure#authentication).

| ACL Required    |
| --------------- |
| `operator:read` |

Usage: `consul operator feature get [options] <name>`

The output looks like this:

```shell-session hideClipboard
$ consul operator feature get peering-multiport-upstreams
Name                         Stage         Desired  Effective  Eligible  Source    Reason            Min Version  Policy Index  Status Index
peering-multiport-upstreams  experimental  true     true       true      operator  operator-enabled  2.1.0        24            24
```

To display every field that the command returns, including the gate's
description and owner, use the `-format=json` option. The JSON output is a list
that contains one object:

```shell-session hideClipboard
$ consul operator feature get -format=json peering-multiport-upstreams
[
  {
    "Name": "peering-multiport-upstreams",
    "Stage": "experimental",
    "MinVersion": "2.1.0",
    "DefaultEnabled": false,
    "BeforeMinimumVersion": "disabled",
    "Description": "Enable multiport peering upstream expansion for proxycfg/xDS",
    "Owner": "xds",
    "DesiredEnabled": true,
    "EffectiveEnabled": true,
    "Eligible": true,
    "Source": "operator",
    "Reason": "operator-enabled",
    "PolicyIndex": 24,
    "StatusIndex": 24
  }
]
```

Refer to [Feature gate states](/consul/docs/manage/feature-gates#feature-gate-states)
for a description of each field.

#### Command Options

- `-format={pretty|json}` - Command output format. The default value is
  `pretty`.

## set

Corresponding HTTP API Endpoint: [\[PUT\] /v1/operator/feature/:name](/consul/api-docs/operator/feature#update-a-feature-gate)

This command enables or disables a feature gate for the datacenter. Consul
records your choice as the desired state and resolves the effective state in the
same operation. Refer to [Feature gate states](/consul/docs/manage/feature-gates#feature-gate-states)
for more information.

The table below shows this command's [required ACLs](/consul/api-docs/api-structure#authentication).

| ACL Required     |
| ---------------- |
| `operator:write` |

Usage: `consul operator feature set [options] <name> <enabled|disabled>`

The value must be `enabled` or `disabled`. The command also accepts `true` and
`false`. You can place options before or after the positional arguments.

The following example enables the `peering-multiport-upstreams` feature gate:

```shell-session hideClipboard
$ consul operator feature set peering-multiport-upstreams enabled
Name                         Stage         Desired  Effective  Eligible  Source    Reason            Min Version  Policy Index  Status Index
peering-multiport-upstreams  experimental  true     true       true      operator  operator-enabled  2.1.0        24            24
```

Setting a gate to the value it already has from an operator is not an error and
does not create a new policy generation.

If you attempt to enable a gate before every server in the datacenter runs the
gate's minimum version, Consul records the desired state, but the effective
state remains `false` until the servers meet the minimum version. The `Reason`
column displays `below-minimum-version`.

### Prevent conflicting updates

Use the `-cas` option to apply a change only if no one else has modified the
feature gate policy since you read it. The value is the `PolicyIndex` that
`consul operator feature get` returns. If the index does not match, Consul does
not change the gate and the command exits with an error.

The following example reads the current policy index and then uses it to update
the gate:

```shell-session hideClipboard
$ INDEX=$(consul operator feature get -format=json peering-multiport-upstreams | jq '.[0].PolicyIndex')
$ consul operator feature set -cas=$INDEX peering-multiport-upstreams disabled
```

If another change has already moved the policy index, the command exits with a
non-zero status and displays the following message:

```shell-session hideClipboard
$ consul operator feature set -cas=1 peering-multiport-upstreams disabled
Feature gate was not updated because policy index 1 did not match
```

An empty or `0` value, or the string `null`, disables the check.

#### Command Options

- `-cas=<index>` - Apply the change only if the current policy index matches
  this value. The default is no check.

- `-format={pretty|json}` - Command output format. The default value is
  `pretty`.
