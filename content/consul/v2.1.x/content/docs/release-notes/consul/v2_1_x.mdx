# Consul 2.1.x

We are pleased to announce the following Consul updates.

## Release highlights

- **Consul Agentic Mesh Platform (beta)**: <EnterpriseAlert inline/> Consul Agentic Mesh Platform (CAMP) extends service mesh governance to AI workloads. Service definitions accept an `ai` block that declares the workload's AI role as `inference-model`, `mcp-server`, or `ai-agent`. The `inference-gateway` service kind enforces intentions and routes requests to model upstreams by capability, with failover across providers by priority. Consul manages OAuth clients for `ai-agent` and `mcp-server` services, and terminating gateways can inject Vault-backed credentials into egress requests. For more information, refer to [Consul Agentic Mesh Platform](/consul/docs/agentic-mesh).
- **API gateway parity with ingress gateway**: The API gateway adds capabilities that were previously available only on the ingress gateway. Consul registers DNS for services exposed through an API gateway at `<service>.api-gateway.consul`. API gateway listeners accept the `http2` and `grpc` protocols for end-to-end HTTP/2 and gRPC traffic. When you enable TLS on an API gateway without configuring a certificate, the gateway terminates TLS with its Connect certificate authority (CA) leaf certificate. You can also configure passive health checks for routed services, and HTTP route header matches support the `invert` field. For more information, refer to [API gateway configuration entry reference](/consul/docs/reference/config-entry/api-gateway) and [HTTP route configuration entry reference](/consul/docs/reference/config-entry/http-route).
- **Hybrid post-quantum TLS**: Consul supports the `X25519MLKEM768` hybrid post-quantum key exchange group for service mesh mutual TLS (mTLS) and agent TLS. The `mesh` configuration entry accepts `TLS.Incoming.ECDHCurves` and `TLS.Outgoing.ECDHCurves`, and agent TLS configuration accepts `tls_ecdh_curves`. When the minimum TLS version is TLS 1.3 and you do not configure curves, Consul offers `X25519MLKEM768` and `X25519` by default. For more information, refer to [Configure post-quantum TLS](/consul/docs/secure/encryption/post-quantum).
- **Sidecar resilience during control plane outages**: Consul delivers leaf certificates and CA roots to sidecar proxies and terminating gateways over Envoy's secret discovery service (SDS). Certificate rotation does not drain established connections. Localized DNS lets the Envoy sidecar resolve virtual service domains locally, so DNS for configured upstreams keeps working when Consul servers are unreachable. Localized DNS is an experimental feature behind the `localized-dns` feature gate, which is disabled by default. For more information, refer to [Certificate authority overview](/consul/docs/secure-mesh/certificate) and [Localized virtual DNS resolution](/consul/docs/connect/proxy/transparent-proxy/localized-dns).
- **OpenID Connect (OIDC) identity provider logout**: Logging out of a token created by an `oidc` auth method can end the session at the identity provider (IdP). `consul logout` prints the IdP's logout URL, or opens it in the default browser with the `-open-browser` flag. The Consul UI opens the URL when you log out. Consul uses the IdP's advertised `end_session_endpoint`, or the `OIDCLogoutURL` auth method setting for providers that do not advertise one. For more information, refer to [OIDC auth method](/consul/docs/secure/acl/auth-method/oidc#oidc-logout).
- **Multiport routing across cluster peers**: <EnterpriseAlert inline/> You can route traffic to a specific named port on a multiport service that a cluster peer exports. Peered multiport routing is an experimental feature behind a feature gate. For more information, refer to [Multiport services across cluster peers](/consul/docs/connect/proxy/multiport#multiport-services-across-cluster-peers) and [Feature gates](/consul/docs/manage/feature-gates).
- **Consul Operations Hub**: <EnterpriseAlert inline/> Consul Operations Hub provides a centralized management view of your Consul datacenters. Consul servers publish snapshots and incremental updates of their data to the Operations Hub global registry. For more information, refer to [Install and set up Consul Operations Hub](/consul/docs/operations-hub).
- **Product telemetry updates**: <EnterpriseAlert inline/> Opt-in telemetry reporting adds product usage metrics for ACL auth methods, audit logging, mesh gateway modes, service intentions, auto-encrypt, API gateways, and transparent proxy adoption. For a complete list of metrics, refer to [Consul agent telemetry reporting reference](/consul/docs/reference/agent/telemetry/reporting).

## Upgrading

Consul 2.1.x includes the following breaking changes:

- Transparent proxy traffic redirection uses `nftables` instead of `iptables`. Redirection requires the `nft` binary and Linux kernel 5.2 or later, or a distribution that backports `nftables` NAT support. Before you upgrade a host or VM in place, remove the `iptables` rules that earlier Consul versions created. The official Consul container images include `nftables` instead of `iptables`. For more information, refer to [Enable transparent proxy mode on VMs](/consul/docs/connect/proxy/transparent-proxy/vm).
- <EnterpriseAlert inline/> Consul limits agent HTTP API and resource API request bodies to 512 KiB by default. Oversized requests return HTTP 413. To raise the limit, set `limits.http_max_request_body_size`.
- <EnterpriseAlert inline/> `GET /v1/agent/connect/ca/leaf/:service` requires `service:write` on the requested service for every request, including requests served from the agent cache.
- <EnterpriseAlert inline/> `Catalog.Register` requires write permission on the node or service of an existing health check to update it.

For more detailed information, refer to the [upgrade details page](/consul/docs/upgrade/version-specific#consul-2-1-x) and the changelogs.
