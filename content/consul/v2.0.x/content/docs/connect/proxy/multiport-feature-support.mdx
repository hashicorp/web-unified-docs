# Multiport feature support

@include 'alerts/enterprise-alert.mdx'

This page summarizes the support status of Consul service mesh features when used with [multiport services](/consul/docs/connect/proxy/multiport). Use this page to understand which multiport capabilities are generally available today, which are planned for an upcoming release, and which are not currently supported.

## Support levels

- **v2.0.x**: Generally available in the current release line.
- **v2.1.x (planned)**: Implemented on the development branch and targeted for the next minor release. Functionality may still change before release.
- **Not planned**: Not currently supported and not on the committed roadmap.

<Note>

Some rows below are still being validated internally and may be revised as engineering confirms final scope. Contact your Consul account team for the latest status on any item marked as not planned.

</Note>

## Feature support matrix

| Feature | v2.0.x | v2.1.x (planned) | Not planned |
| --- | --- | --- | --- |
| Cross-partition | Partial<sup>1</sup> | — | — |
| Cluster peering | — | Yes<sup>2</sup> | — |
| WAN federation | — | — | Not planned |
| Upstream: transparent proxy mode | Yes | — | — |
| Upstream: non-transparent proxy mode | Yes | — | — |
| Multi-protocol (L7) | Partial<sup>3</sup> | Yes<sup>3</sup> | — |
| API gateway | — | — | Not planned |
| Terminating gateway | — | — | Not planned |
| Discovery chain: splitter, resolver, and router | Partial<sup>3</sup> | Yes<sup>3</sup> | — |
| Proxy and service defaults: destination port | Yes | — | — |
| Proxy and service defaults: source port | — | — | Not planned |
| Escape hatches, fault injection, and other overrides | — | — | Not planned |
| Port-specific intentions (ACLs) | Partial<sup>4</sup> | — | — |
| Per-port TLS permissiveness override | — | — | Not planned |
| Per-port metrics and tracing | Partial<sup>5</sup> | — | — |
| Port-wise health checks and reconciliation | — | Yes<sup>6</sup> | — |
| Platform: Kubernetes | Yes | — | — |
| Platform: ECS, ESM, and Terraform modules | — | — | Not planned |
| DNS compatibility | Partial<sup>7</sup> | — | — |
| DNS: localized DNS | — | — | Not planned |
| DNS: prepared queries | — | Yes | — |
| Passthrough mode (transparent proxy) | — | — | Not planned |
| Per-port watches and scale testing | — | — | Not planned |

<sup>1</sup> Validated for Kubernetes with Consul admin partitions; other platforms aren't separately validated.

<sup>2</sup> Adds the ability to route traffic to named ports on a peered multiport service.

<sup>3</sup> Only the default port fully traverses a configured `service-router`, `service-splitter`, or `service-resolver` today. Named, non-default ports connect directly to the destination port instead of returning an error. A **v2.0.4** patch prevents connection failures for this case; full parity across all named ports is planned for **v2.1.x**.

<sup>4</sup> Intentions are enforced at the service level. Named-port virtual IPs resolve to the base service for intention evaluation.

<sup>5</sup> Each named port gets its own Envoy cluster, enabling per-cluster metrics. Distributed tracing doesn't yet include port-level tags.

<sup>6</sup> Ensures older agents receive correct port data across catalog, health checks, prepared queries, and streaming.

<sup>7</sup> Named ports resolve via DNS SRV lookups; other record types don't disambiguate between ports.
