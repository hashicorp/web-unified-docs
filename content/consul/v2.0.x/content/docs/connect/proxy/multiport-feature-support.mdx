# Multiport feature support

@include 'alerts/enterprise-alert.mdx'

This page summarizes the support status of Consul service mesh features when used with [multiport services](/consul/docs/connect/proxy/multiport).

## Applicability

This support matrix applies to Consul Enterprise 2.0.x and later. The documented behavior was validated with Consul on Kubernetes (`consul-k8s` and the `consul` Helm chart) 2.0.x and later. Refer to [Consul Kubernetes compatibility](/consul/docs/upgrade/k8s/compatibility) for the exact Envoy, Consul dataplane, Kubernetes, and OpenShift versions supported by your release.

<Note>

Multiport service mesh routing is available in Consul Enterprise. Support varies by capability, configuration, and deployment platform. Review this matrix before using multiport services in production.

</Note>

## Status definitions

- **Yes**: Supported and validated in the stated scope.
- **Partial**: Supported only with the listed limitations.
- **No**: Unsupported.
- **Not validated**: The combination has not been formally validated and is outside the documented support scope.

## Feature support matrix

| Feature | Status | Description |
| --- | --- | --- |
| Multi-port registration in an admin partition | Yes | A multiport service registers in an admin partition the same way as any other service. |
| Cross-partition communication with multi-port services | Yes | Validated on Kubernetes through mesh gateways, using a service registered in an admin partition. Other deployment platforms haven't been formally validated and are outside the scope of this support statement. |
| Cluster peering | No | Not currently supported. |
| Upstream: transparent proxy mode | Yes | — |
| Upstream: non-transparent proxy mode | Yes | — |
| Different application protocols on named ports | Partial | Named ports can carry different network traffic, such as HTTP and gRPC, when the service doesn't declare an application protocol. Consul supports only one declared L7 protocol per service, and that setting applies to every named port. |
| L7 traffic management across named ports | Partial | The default port can use service-level L7 traffic management, such as HTTP-aware routing. Named, non-default ports connect directly to the destination port and bypass L7-aware processing. |
| API gateway | No | Not currently supported. |
| Terminating gateway | No | Not currently supported. |
| Ingress gateway | No | [Ingress gateway](/consul/docs/north-south/ingress-gateway) is deprecated. |
| Mesh gateways | Yes | Mesh gateways forward traffic to each named port using the port name encoded in ALPN. Default and non-default named ports use the same forwarding mechanism. |
| WAN federation | No | Multiport routing across WAN-federated datacenters isn't supported. |
| Service router | Partial | Only traffic to the default port traverses a configured service router. Named, non-default ports connect directly to the destination port and bypass the router. |
| Service splitter | Partial | Only traffic to the default port traverses a configured service splitter. Named, non-default ports connect directly to the destination port and bypass traffic splitting. |
| Resolver subsets | Partial | Only traffic to the default port resolves through configured resolver subsets. Named, non-default ports connect directly to the destination port. |
| Resolver redirects | Partial | Only traffic to the default port follows a configured resolver redirect. Named, non-default ports connect directly to the destination port. |
| Resolver failover | Partial | Only traffic to the default port benefits from configured resolver failover. Named, non-default ports have no automatic failover. |
| Load-balancing policy | Partial | Only traffic to the default port applies a configured load-balancing policy. Named, non-default ports connect directly to the destination port. |
| Proxy and service defaults: destination port | No | Not currently supported. |
| Proxy and service defaults: source port | No | Not currently supported. |
| Escape hatches, fault injection, and other overrides | No | Not currently supported. |
| Service-level intentions | Yes | Consul evaluates intentions against the multiport service identity. An allow or deny decision applies to every named port registered under that identity. |
| Port-specific intentions (ACLs) | No | Independent allow or deny policies can't be applied to individual named ports. Register ports as separate Consul services when they require different authorization policies. |
| Per-port TLS permissiveness override | No | Not currently supported. |
| Per-port metrics | Yes | Each named port is represented by a distinct Envoy cluster, so proxy metrics can be segmented by cluster. Not every Consul control-plane metric includes a port label. |
| Per-port tracing | No | Consul doesn't add built-in named-port attributes to distributed traces. Applications may create their own custom trace attributes, but Consul doesn't automatically provide port-level trace attribution. |
| Port-wise health checks and reconciliation | No | Not currently supported. |
| Platform: Kubernetes | Yes | — |
| Platform: ECS, ESM, and Terraform modules | No | Not currently supported. |
| Consul DNS SRV records | Yes | Named ports resolve via DNS SRV lookups. |
| DNS A and AAAA records | No | A and AAAA records don't carry port-level information and can't disambiguate between named ports. |
| Transparent proxy virtual DNS | Yes | `<port-name>.<service-name>.virtual.consul` identifies the named service-port destination and resolves to the corresponding virtual IP. |
| DNS: localized DNS | No | Not currently supported. |
| DNS: prepared queries | No | Not currently supported. |
| Passthrough mode (transparent proxy) | Not validated | Passthrough mode uses Envoy's original destination cluster to route traffic without modifying the destination. This mechanism has not been formally validated with multiport services and is outside the documented support scope. |
| Multiport scale envelope | Not validated | Consul doesn't publish a multiport-specific tested scale envelope, such as maximum ports per service, maximum multiport services per datacenter, or maximum named-port upstreams per proxy. Validate scale requirements for your workload before production use. |
