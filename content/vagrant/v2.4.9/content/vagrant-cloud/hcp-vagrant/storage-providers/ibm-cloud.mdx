# Migrate to IBM Cloud Object Storage

@include "@global/vagrant-eol.mdx"

This guide describes how to move your Vagrant boxes from HCP Vagrant Registry to
IBM Cloud Object Storage and reference them from a Vagrantfile. You use the IBM
Cloud command line interface (CLI) and its Cloud Object Storage plugin to create
a storage instance, create a bucket, upload your boxes, and optionally serve them
publicly.

## Overview

IBM Cloud Object Storage organizes data in a hierarchy. A service instance is the
highest level of organization. Each instance can hold many buckets, and each
bucket can hold virtually any number of objects, such as your `vagrant.box`
files. In this guide you create one service instance, add a bucket to it, and
upload your boxes as objects.

## Prerequisites

Before you begin, complete the following:

- Download the boxes you want to migrate from HCP Vagrant Registry so that you
  have the `vagrant.box` files available locally.
- Create an [IBM Cloud account](https://cloud.ibm.com/registration). This guide
  uses a free account, which supports the `lite` plan.

## Install the IBM Cloud CLI

Install the IBM Cloud CLI by following the
[IBM Cloud CLI getting started guide](https://cloud.ibm.com/docs/cli?topic=cli-getting-started).

## Log in and target a region

Log in to IBM Cloud:

```shell-session
$ ibmcloud login
```

Select a region either by passing `-r REGION` with the login command or by
setting it afterward with `ibmcloud target`:

```shell-session
$ ibmcloud login -r REGION
```

```shell-session
$ ibmcloud target -r REGION
```

The login command supports many additional options, such as single sign-on and
API key authentication. Refer to the
[IBM Cloud CLI getting started guide](https://cloud.ibm.com/docs/cli?topic=cli-getting-started)
for the full list.

## Target a resource group

Target the `Default` resource group:

```shell-session
$ ibmcloud target -g Default
```

To list the resource groups available to your account, run the following command:

```shell-session
$ ibmcloud resource groups
```

If you want to use a custom resource group instead of `Default`, refer to the
[IBM Cloud resource commands reference](https://cloud.ibm.com/docs/cli?topic=cli-ibmcloud_commands_resource).

## Install the Cloud Object Storage plugin

The IBM Cloud Object Storage plugin extends the IBM Cloud CLI with an API wrapper
for working with object storage resources. Install it with the following command:

```shell-session
$ ibmcloud plugin install cloud-object-storage
```

For more details, refer to the
[IBM Cloud Object Storage CLI documentation](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-ic-cos-cli).

## Create a Cloud Object Storage service instance

Create a service instance to hold your buckets:

```shell-session
$ ibmcloud resource service-instance-create INSTANCE_NAME cloud-object-storage PLAN global
```

To list the available plans, run the following command:

```shell-session
$ ibmcloud catalog service cloud-object-storage
```

A free account supports the `lite` plan. Other options include `standard` and
`onerate`.

## Create a bucket

Create a bucket in your service instance:

```shell-session
$ ibmcloud cos bucket-create --bucket BUCKET_NAME [--class CLASS_NAME] [--ibm-service-instance-id ID] [--region REGION] [--output FORMAT]
```

When you use IAM authentication, you must pass `--ibm-service-instance-id`. Fetch
the ID of the instance you created in the previous step with its Cloud Resource
Name (CRN):

```shell-session
$ ibmcloud resource service-instance INSTANCE_NAME --crn
```

For more options, refer to
[Create a new bucket](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-ic-cos-cli#create-a-new-bucket).

## Upload a box

Upload a box to the bucket. Use `--key` to set the object path within the bucket
and `--file` to point to the local `vagrant.box` file:

```shell-session
$ ibmcloud cos upload --bucket BUCKET_NAME --key KEY --file PATH_TO_BOX
```

For example, a `--key` such as `BOX_NAME/VERSION/PROVIDER/ARCHITECTURE/vagrant.box`
keeps your boxes organized by version, provider, and architecture. For more upload
options, refer to
[Upload objects by using s3manager](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-ic-cos-cli#upload-objects-by-using-s3manager).

## Make the bucket public

Buckets can be public or private. If you want Vagrant to download boxes without
authentication, make the bucket public by granting the `Content Reader` role to
the public access group:

```shell-session
$ ibmcloud iam access-group-policy-create "Public Access" --roles "Content Reader" --service-name cloud-object-storage --service-instance INSTANCE_ID --resource-type bucket --resource BUCKET_NAME
```

For more details, refer to
[ibmcloud iam access-group-policy-create](https://cloud.ibm.com/docs/cli?topic=cli-ibmcloud_commands_iam#ibmcloud_iam_access_group_policy_create).

~> **Warning:** A public bucket allows anyone to download its objects. Only make
a bucket public if the boxes it contains are safe to distribute publicly.

## Reference a box from a public bucket

For a public bucket, the object link has the following form:

```text
https://BUCKET_NAME.s3.REGION.cloud-object-storage.appdomain.cloud/KEY
```

Reference the box in your Vagrantfile with `config.vm.box_url`:

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "BOX_NAME"
  config.vm.box_url = "IBM_COS_URL"
end
```

## Reference a box from a private bucket

For a private bucket, the box is not available at a public URL, so download it
first and add it to Vagrant locally.

Download the box object from the bucket. Provide the `--key` of the object and a
local file name as the final argument:

```shell-session
$ ibmcloud cos object-get --bucket BUCKET_NAME --key KEY LOCAL_FILE
```

Add the downloaded box to Vagrant under a name of your choice:

```shell-session
$ vagrant box add BOX_NAME LOCATION
```

`LOCATION` is the path to the box file you downloaded in the previous step. For
more options, refer to
[vagrant box add](/vagrant/docs/cli/box#box-add).

After you add the box, reference it directly in your Vagrantfile by name:

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "BOX_NAME"
end
```
