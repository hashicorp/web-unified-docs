# Native tasks API reference

Native tasks are tasks whose integration is built into HCP Terraform. Unlike a run task (`category: "task"` or `"hook"`), you do not supply a webhook `url` or `hmac-key`. Instead, you pick an integration from the list of available integrations and supply the parameters that integration requires, such as an API URL and credentials. HCP Terraform then runs the integration for you at the stages the integration supports. A native task has `category` set to `"native"`.

This page lists the API endpoints for creating and updating native tasks, and discovering integrations. Refer to the [task stages and results API reference](/terraform/cloud-docs/api-docs/tasks/task-stages-and-results) for the endpoints that read task results and their outcomes. Refer to the [tasks API reference](/terraform/cloud-docs/api-docs/tasks/tasks) for the endpoints that list, show, and delete tasks and associate them to workspaces. Those endpoints work the same for native tasks. For run tasks, which send a payload to a URL that you host, refer to the [run tasks API reference](/terraform/cloud-docs/api-docs/tasks/run-tasks).

~> **Note:** The Cloudability native task is currently in public beta, and is available in Terraform Enterprise, HCP Terraform **Standard**, and HCP Terraform **Premium** editions. Refer to [HCP Terraform pricing](https://www.hashicorp.com/products/terraform/pricing) for details.

## Required permissions

The organization and workspace permissions for native tasks are the same as for run tasks. Refer to [Required permissions](/terraform/cloud-docs/api-docs/tasks/tasks#required-permissions) in the tasks API reference. The organization must have the `native-tasks` [feature entitlement](/terraform/cloud-docs/api-docs#feature-entitlements).

## List integrations

`GET /tasks/integrations`

Lists the integrations that you can use to create a native task. By default, only active integrations are returned.

| Status  | Response                                       | Reason                 |
| ------- | ---------------------------------------------- | ---------------------- |
| [200][] | [JSON API document][] (`type: "integrations"`) | Request was successful |
| [401][] | [JSON API error object][]                      | Unauthorized           |

### Query parameters

This endpoint supports pagination [with standard URL query parameters](/terraform/cloud-docs/api-docs#query-parameters). Remember to percent-encode `[` as `%5B` and `]` as `%5D` if your tooling doesn't automatically encode URLs.

| Parameter          | Description                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `search`           | **Optional.** Returns only integrations whose name contains this value. The match is case-insensitive and partial. |
| `include_inactive` | **Optional.** Set to `true` to include inactive integrations. If omitted, only active integrations are returned.   |
| `page[number]`     | **Optional.** If omitted, the endpoint will return the first page.                                                 |
| `page[size]`       | **Optional.** If omitted, the endpoint will return 20 integrations per page.                                       |

### Integration attributes

| Attribute     | Type   | Description                                                                                                                          |
| ------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `name`        | string | The display name of the integration.                                                                                                 |
| `provider`    | string | The provider identifier, for example `cloudability`.                                                                                 |
| `description` | string | A description of what the integration does.                                                                                          |
| `homepage`    | string | The integration's home page URL.                                                                                                     |
| `stages`      | array  | The run stages where the integration can run. One or more of `pre_plan`, `post_plan`, `pre_apply`, or `post_apply`.                  |
| `params`      | array  | The ordered list of parameters the integration needs. Refer to [Integration parameter attributes](#integration-parameter-attributes). |

#### Integration parameter attributes

Each entry in `params` describes one value you must (or may) supply under `data.attributes.params` when you create a native task.

| Attribute     | Type   | Description                                                                                                                   |
| ------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `paramId`     | string | The identifier of the parameter, with dashes. Replace the dashes with underscores to get the key under `data.attributes.params`. |
| `name`        | string | Display name of the parameter.                                                                                                |
| `kind`        | string | The type of input, for example `string`, `url`, or `choice`.                                                                  |
| `required`    | bool   | Whether you must supply this parameter.                                                                                       |
| `sensitive`   | bool   | Whether the value is a secret. Sensitive values are write-only and are returned as `null` in task responses.                  |
| `description` | string | Description of the parameter.                                                                                                 |
| `placeholder` | string | Optional example value.                                                                                                       |
| `validation`  | object | Optional. A `regex` the value must match and the `errorMsg` returned when it does not.                                        |
| `values`      | array  | Optional. For `choice` parameters, the list of suggested `key`/`value` pairs.                                                 |

### Sample request

```shell
curl \
  --header "Authorization: Bearer $TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  "https://app.terraform.io/api/v2/tasks/integrations?search=cloud&page%5Bsize%5D=20"
```

## Create a native task

`POST /organizations/:organization_name/tasks`

| Parameter            | Description                                                                                                                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `:organization_name` | The organization to create the task in. The organization must already exist in HCP Terraform, must have the `native-tasks` [feature entitlement](/terraform/cloud-docs/api-docs#feature-entitlements), and must have the `CLOUDABILITY_NATIVE_RUN_TASK` feature flag enabled. |

| Status  | Response                                | Reason                                                                                                                                                                         |
| ------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [201][] | [JSON API document][] (`type: "tasks"`) | Successfully created a native task                                                                                                                                             |
| [403][] | [JSON API error object][]               | The organization has reached its run task limit                                                                                                                                |
| [404][] | [JSON API error object][]               | Organization not found, user unauthorized to perform action, the organization is not entitled to `native-tasks`, or the `CLOUDABILITY_NATIVE_RUN_TASK` feature flag is off for the organization |
| [422][] | [JSON API error object][]               | Malformed request body (missing integration, unknown integration, missing required `params`, and so on)                                                                       |

### Request body

This POST endpoint requires a JSON object with the following properties as a request payload.

Properties without a default value are required unless otherwise specified.

| Key path | Type | Default | Description |
| --- | --- | --- | --- |
| `data.type` | string | | Must be `"tasks"`. |
| `data.attributes.category` | string | | Must be `"native"`. |
| `data.attributes.name` | string | | The name of the task. Can include letters, numbers, `-`, and `_`. |
| `data.attributes.description` | string | | (Optional) The description of the task. Can be up to 300 characters long including spaces, letters, numbers, and special characters. |
| `data.attributes.enabled` | bool | `true` | (Optional) Whether the task will be run. |
| `data.attributes.params` | object | | The parameters for the integration, keyed by the `paramId` of each entry in the integration's `params` list, with dashes written as underscores (for example `cloudability_url` for `cloudability-url`). You must supply every parameter marked `required`. Do not send `url` or `hmac-key` for native tasks. |
| `data.attributes.global-configuration` | object | | (Optional) The global configuration object. Ignored if a `task-configs` relationship is present. If a `task-configs` relationship is not present, it will create a task configuration owned by the organization. |
| `data.attributes.global-configuration.enabled` | bool | `false` | (Optional) Whether the task will be associated on all workspaces. |
| `data.attributes.global-configuration.stages` | array | | (Optional) An array of strings representing the stages of the run lifecycle when the task should begin. Must be one or more of `"pre_plan"`, `"post_plan"`, `"pre_apply"`, or `"post_apply"`. Use the `stages` that the integration lists, because the integration only runs at those stages. |
| `data.attributes.global-configuration.enforcement-level` | string | | (Optional) The enforcement level of the task. Must be `"advisory"` or `"mandatory"`. |
| `data.relationships.integration.data.id` | string | | The `int-*` external ID of the integration, as returned by [List integrations](#list-integrations). |
| `data.relationships.integration.data.type` | string | | Must be `"integrations"`. |
| `data.relationships.agent-pool.data.id` | string | | (Optional) The agent pool that HCP Terraform uses to make requests for the task. Requires [HCP Terraform Premium plan](https://www.hashicorp.com/en/pricing?tab=terraform), the [`private-run-tasks` feature entitlement](/terraform/cloud-docs/api-docs#feature-entitlements), and a self-hosted HCP Terraform agent. |
| `data.relationships.task-configs.data` | list of objects | | (Optional) The [task configurations](/terraform/cloud-docs/api-docs/tasks/task-configs) for the task. Refer to [Create a run task](/terraform/cloud-docs/api-docs/tasks/run-tasks#create-a-run-task) for the nested properties. |

#### Sensitive parameters

Parameters marked `sensitive: true` are write-only. HCP Terraform stores them encrypted and returns `null` for them in every response.

### Sample payload

```json
{
  "data": {
    "type": "tasks",
    "attributes": {
      "category": "native",

    }
  }
}
```

## Update a native task

`PATCH /tasks/:id`

Updates a native task. The endpoint is the same as for run tasks, but a native task takes its integration settings in `data.attributes.params` instead of `url` and `hmac-key`.

| Parameter | Description                                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `:id`     | The ID of the task to update, for example `task-7oD7doVTQdAFnMLV`. Use the [List tasks](/terraform/cloud-docs/api-docs/tasks/tasks#list-tasks) endpoint to find IDs. |

| Status  | Response                                | Reason                                                                                                                                                                         |
| ------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [200][] | [JSON API document][] (`type: "tasks"`) | Successfully updated the task                                                                                                                                                  |
| [404][] | [JSON API error object][]               | Task not found, user unauthorized to perform action, the organization is not entitled to `native-tasks`, or the `CLOUDABILITY_NATIVE_RUN_TASK` feature flag is off for the organization |
| [422][] | [JSON API error object][]               | Malformed request body                                                                                                                                                         |

### Request body

This PATCH endpoint requires a JSON object with the following properties as a request payload.

`data.type` is required. All other properties are optional, and omitted properties keep their previous value.

| Key path | Type | Default | Description |
| --- | --- | --- | --- |
| `data.type` | string | | Must be `"tasks"`. |
| `data.attributes.name` | string | (previous value) | The name of the task. Can include letters, numbers, `-`, and `_`. |
| `data.attributes.description` | string | (previous value) | The description of the task. Can be up to 300 characters long including spaces, letters, numbers, and special characters. |
| `data.attributes.enabled` | bool | (previous value) | Whether the task will be run. |
| `data.attributes.params` | object | (previous value) | The parameters for the integration, keyed the same way as when you [create a native task](#create-a-native-task). This replaces the stored params, so send every param you want to keep. Refer to [Sensitive parameters on update](#sensitive-parameters-on-update). |
| `data.attributes.global-configuration` | object | | The global configuration object. If it is present, it will create or update a task configuration owned by the organization. |
| `data.attributes.global-configuration.enabled` | bool | `false` | Whether the task will be associated on all workspaces. |
| `data.attributes.global-configuration.stages` | array | | An array of strings representing the stages of the run lifecycle when the task should begin. Must be one or more of `"pre_plan"`, `"post_plan"`, `"pre_apply"`, or `"post_apply"`. Use the `stages` that the integration lists, because the integration only runs at those stages. |
| `data.attributes.global-configuration.enforcement-level` | string | | The enforcement level of the task. Must be `"advisory"` or `"mandatory"`. |
| `data.relationships.agent-pool.data.id` | string | | The agent pool that HCP Terraform uses to make requests for the task. Requires [HCP Terraform Premium plan](https://www.hashicorp.com/en/pricing?tab=terraform) and the [`private-run-tasks` feature entitlement](/terraform/cloud-docs/api-docs#feature-entitlements). |

#### Sensitive parameters on update

If a parameter is marked `sensitive: true` in the integration, HCP Terraform never returns its value. When you update `params`, include the sensitive parameter with a blank value to keep the stored value, or with a new value to replace it. If you omit the key entirely, the stored value is removed along with any other omitted param.

#### Fields you cannot change

You cannot change the integration of an existing task. The update endpoint does not accept the `integration` relationship. To use a different integration, create a new native task. Do not send `url` or `hmac-key` for a native task.

### Sample payload

```json
{
  "data": {
    "type": "tasks",
    "attributes": {
      "name": "cloudability-cost-estimate-eu",
      "enabled": true,
      "params": {
        "cloudability_url": "https://api-eu.cloudability.com",
        "frontdoor_url": "https://frontdoor-eu.apptio.com",
        "access_key": "",
        "secret_key": "",
        "apptio_environment_id": "00000000-0000-0000-0000-000000000000"
      }
    }
  }
}
```

In this payload, `access_key` and `secret_key` are sensitive and blank, so HCP Terraform keeps their stored values.

### Sample request

```shell
curl \
  --header "Authorization: Bearer $TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  --request PATCH \
  --data @payload.json \
  https://app.terraform.io/api/v2/tasks/task-7oD7doVTQdAFnMLV
```
