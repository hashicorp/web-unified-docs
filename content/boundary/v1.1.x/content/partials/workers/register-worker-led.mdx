<Tab heading="Admin UI" group="ui">

Complete the following steps to register the worker using the Admin UI:

1. Log in to Boundary as the admin user.

1. Select **Workers** in the navigation pane.

1. Click **New**.

1. (Optional) You can use the **New PKI Worker** page to construct the contents of the worker configuration file, if you did not [create the configuration file](/boundary/docs/workers/create) already.
Provide the following details, and Boundary constructs the worker configuration file for you:
   - Boundary Cluster ID
   - Worker public address
   - Config file path
   - Worker Tags
   - Local Session Recording Storage

1. Under **Confirm the worker when they connect**, paste the **Worker Auth Registration Request** key.
Boundary prints the **Worker Auth Registration Request** key in the CLI output when you start the worker.
You can also read the value from the `auth_request_token` file in the worker's `auth_storage_path` directory.

1. Click **Register Worker**.
Boundary marks the registration request as **Registered**.

1. Click **Done**.

  Boundary returns you to the **Workers** page, where the new worker appears in the list.

</Tab>

<Tab heading="CLI" group="cli">

Complete the following steps to register the worker using the CLI:

1. Set the `BOUNDARY_ADDR` environment variable to the address of your Boundary cluster:

  ```shell-session
  $ export BOUNDARY_ADDR="https://boundary.example.com:9200"
  ```

1. Log in to the CLI as the admin user.
Provide the auth method ID and admin login name, and enter the password when Boundary prompts you for it:

  ```shell-session
  $ boundary authenticate password \
    -auth-method-id=ampw_nihdQAQjRN \
    -login-name=admin
  ```

  Boundary returns the authentication information and stores the token in your keyring:

  <CodeBlockConfig hideClipboard>

  ```plaintext
  Authentication information:
    Account ID:      acctpw_mGfnmjtath
    Auth Method ID:  ampw_nihdQAQjRN
    Expiration Time: Fri, 14 Aug 2026 13:44:25 MDT
    User ID:         u_GENi0SquNe

  The token name "default" was successfully stored in the chosen keyring and is not displayed here.
  ```

  </CodeBlockConfig>

1. Export the **Worker Auth Registration Request** value as an environment variable.
Boundary prints this value when you start the worker, and also writes it to the `auth_request_token` file in the worker's `auth_storage_path` directory:

  ```shell-session
  $ export WORKER_TOKEN=$(cat /var/lib/boundary/auth_request_token)
  ```

1. Register the worker using the worker-led method:

  ```shell-session
  $ boundary workers create worker-led -worker-generated-auth-token=$WORKER_TOKEN
  ```

  Boundary returns the new worker resource:

  <CodeBlockConfig hideClipboard>

  ```plaintext
  Worker information:
    Active Connection Count:   0
    Created Time:              Fri, 07 Aug 2026 13:44:30 MDT
    ID:                        w_UJ3Qq63Jx0
    Local Storage State:       unknown
    Type:                      pki
    Updated Time:              Fri, 07 Aug 2026 13:44:30 MDT
    Version:                   1

    Scope:
      ID:                      global
      Name:                    global
      Type:                    global

    Authorized Actions:
      no-op
      read
      update
      delete
      add-worker-tags
      set-worker-tags
      remove-worker-tags
  ```

  </CodeBlockConfig>

  The `Local Storage State` value is `unknown` until the worker reports its first status to the controller.

</Tab>
</Tabs>

After the worker registers, Boundary deletes the `auth_request_token` file from the worker's `auth_storage_path` directory.
The activation token is single use, so you cannot register the same worker twice with the same token.
