# Boundary MCP server overview

The Boundary Model Context Protocol (MCP) server connects AI assistants to the Boundary API so that you can inspect and manage Boundary resources, such as targets, sessions, users, and roles, using natural language.

@include 'alerts/beta.mdx'

MCP is an open standard that lets AI applications call external tools and read data from external systems. Any MCP client that supports the Streamable HTTP transport can connect to the Boundary MCP server. For example, you can use Visual Studio Code, Cursor, Claude Desktop, Amazon Q Developer, or IBM Bob.

## How the Boundary MCP server works

The MCP server sits between your MCP client and a Boundary controller. When you enter a prompt, the AI model selects an MCP tool, and the MCP client sends the request to the MCP server. The server calls the Boundary API on your behalf and returns the result to the model.

The server does not hold its own permissions. Each user supplies a Boundary token, and the Boundary controller authorizes every API operation against that user's roles and grants. An assistant can only do what the token's owner can do. Refer to the [Boundary MCP server security model](/boundary/docs/mcp-server/security-model) for details.

## Supported resources and toolsets

The server groups its tools into toolsets. A **toolset** is a set of related tools for one Boundary resource type. Most resource types have a read toolset that lists and reads resources, and an admin toolset that creates, updates, and deletes them.

The server provides toolsets for the following resource types:

- Targets
- Sessions
- Users, groups, managed groups, and roles
- Accounts and auth methods
- Scopes
- Workers
- Host catalogs, host sets, and hosts
- Credential stores, credential libraries, and credentials
- Storage buckets and session recordings
- Aliases
- Policies

By default, the server enables only the `targets` and `sessions` toolsets. You choose which toolsets to enable when you start the server, which lets you limit an assistant to read-only inspection or grant it administrative access.

In local mode, the server also provides a `connect` toolset. It starts a local proxy session to a target on your local machine.

### Unsupported operations

The Boundary MCP server does not support any Boundary API endpoint that handles secrets. AI assistants must not read secrets, so the server does not accept or return them.

For example, the server does not support the following operations:

- Creating static credentials
- Creating Vault credential stores
- Setting a password when you create or update an account

The server can still read, list, update, and delete the non-secret values of a resource. For example, you can change the name or description of a static credential.

The server also does not support credential brokering, because brokering returns credentials to the requester. To use the `connect` toolset, [configure the target for credential injection](/boundary/docs/credentials/configure-credential-injection), so that Boundary supplies credentials to the session and never to the assistant or the model.
