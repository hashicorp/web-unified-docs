# Controller values

You configure the Boundary controller Helm chart with Helm values and a Boundary HCL configuration. This page documents the Helm values you use to deploy the controller on Red Hat OpenShift, including the shared chart values and the OpenShift-specific values. The chart is the source of truth for supported values.

## Secret reference values

| Key | Default | Description |
| --- | --- | --- |
| `secretRefs.secretName` | `boundary-controller-secrets` | Name of an existing Kubernetes Secret that contains the values referenced by `secretRefs.keys` |
| `secretRefs.validateExisting` | `false` | When `true`, looks up the referenced Secret and checks the keys required by the rendered HCL and enabled bootstrap Job during rendering. Requires cluster lookup access. |
| `secretRefs.keys.databaseUrl` | `database-url` | Key in the Secret used for `env://BOUNDARY_PG_URL` in `controller.config`. Set to the key name used in your Secret. |
| `secretRefs.keys.migrationUrl` | `migration-url` | Key in the Secret used for `env://BOUNDARY_PG_MIGRATION_URL` in `controller.config`. Required only when referenced in `controller.config`. Set to the key name used in your Secret. |
| `secretRefs.keys.license` | `license` | Key in the Secret used for `env://BOUNDARY_LICENSE` in `controller.config`. Set to the key name used in your Secret. |
| `secretRefs.keys.adminUsername` | `admin-username` | Key in the Secret whose value is used by the bootstrap admin Job. Set to the key name used in your Secret. |
| `secretRefs.keys.adminPassword` | `admin-password` | Key in the Secret whose value is used by the bootstrap admin Job. Set to the key name used in your Secret. |

The `secretRefs.keys` values are key names inside your Kubernetes or OpenShift Secret. The chart mounts no Secret as a file. Instead, it conditionally creates environment variables from Secret key references when the rendered HCL uses `env://BOUNDARY_PG_URL`, `env://BOUNDARY_PG_MIGRATION_URL`, or `env://BOUNDARY_LICENSE`. The bootstrap Job always references the administrator keys when enabled.

Validation is targeted. With `secretRefs.validateExisting=true`, the chart checks only the keys used by the rendered configuration and enabled bootstrap settings. With the default `false`, Kubernetes reports a missing Secret or key when it creates a pod. Neither mode validates the values or external service connectivity.

## Extra volume and manifest values

| Key | Default | Description |
| --- | --- | --- |
| `extraVolumes` | `[]` | Additional Kubernetes or OpenShift volumes added to the controller Deployment pod. The chart does not add them to hook Jobs. |
| `extraVolumeMounts` | `[]` | Additional volume mounts added to the controller container. Each mount must reference a volume available to the controller pod. The chart does not add them to hook Jobs. |
| `extraManifests` | `[]` | Additional Kubernetes manifests rendered with Helm's `tpl` function. Accepts a list or map whose entries are YAML objects or YAML strings. |

The chart renders each supported `extraManifests` entry as a separate YAML document. Kubernetes applies these resources as part of the Helm release, but the chart does not otherwise validate or modify them.

## OpenShift values

Set `openshift.enabled=true` to render OpenShift Routes, use security contexts that let a security context constraint (SCC) assign user and group IDs, and select the Red Hat certified image defaults. OpenShift mode does not change the configured Service types. The OpenShift security contexts apply to the controller Deployment and all hook Jobs.

| Key | Default | Description |
| --- | --- | --- |
| `openshift.enabled` | `false` | Enables OpenShift Routes, SCC-compatible security contexts, and Red Hat image resolution. |

The chart evaluates the remaining values under `openshift` only when OpenShift mode is enabled.

### OpenShift image resolution

OpenShift mode changes the resolved image only when you leave the corresponding shared image value empty.

| Key | Default | OpenShift behavior |
| --- | --- | --- |
| `image.repository` | `""` | Resolves to `registry.connect.redhat.com/hashicorp/boundary-enterprise` when `openshift.enabled=true`. An explicit value takes precedence. |
| `image.tag` | `""` | Resolves to `Chart.appVersion` plus `-ubi`, which is `1.0.2-ent-ubi` in chart `0.2.0`. An explicit value takes precedence. |

The Red Hat registry requires authentication. Reference a pull Secret in the shared `imagePullSecrets` value, or link one to the ServiceAccount used by the controller. The shared `image.pullPolicy` behavior does not change in OpenShift mode.

### OpenShift security context values

When `openshift.enabled=true`, these values replace the shared `podSecurityContext` and `containerSecurityContext` on the Deployment and hook Jobs.

| Key | Default |
| --- | --- |
| `openshift.podSecurityContext.runAsNonRoot` | `true` |
| `openshift.podSecurityContext.seccompProfile.type` | `RuntimeDefault` |
| `openshift.containerSecurityContext.runAsNonRoot` | `true` |
| `openshift.containerSecurityContext.allowPrivilegeEscalation` | `false` |
| `openshift.containerSecurityContext.readOnlyRootFilesystem` | `true` |
| `openshift.containerSecurityContext.capabilities.drop` | `ALL` |
| `openshift.containerSecurityContext.seccompProfile.type` | `RuntimeDefault` |

The values omit `runAsUser`, `runAsGroup`, and `fsGroup` so that the project's SCC can assign IDs from its allowed range. The defaults are compatible with the `restricted-v2` SCC and do not require elevated privileges. Do not pin an ID unless the ServiceAccount uses an SCC that permits it.

### API Route values

| Key | Default | Description |
| --- | --- | --- |
| `openshift.route.api.enabled` | `true` | Creates a Route to the API Service. |
| `openshift.route.api.host` | `""` | Sets the Route hostname. OpenShift generates one when empty. |
| `openshift.route.api.tls.termination` | `reencrypt` | Sets `edge`, `reencrypt`, or `passthrough` termination. |
| `openshift.route.api.tls.insecureEdgeTerminationPolicy` | `Redirect` | Sets `Allow`, `Redirect`, or `None` handling for HTTP requests. |
| `openshift.route.api.tls.key` | `""` | Sets the private key for a client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.api.tls.certificate` | `""` | Sets the client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.api.tls.caCertificate` | `""` | Sets the CA certificate chain for the client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.api.tls.destinationCACertificate` | `""` | Sets the CA certificate used to verify the backend for `reencrypt` termination. |
| `openshift.route.api.annotations` | `{}` | Adds annotations to the Route. |
| `openshift.route.api.labels` | `{}` | Adds labels to the Route. |

For `edge` termination, set `tls.api.disabled=true`. For `reencrypt` or `passthrough`, set `tls.api.disabled=false`. For `reencrypt`, also set `destinationCACertificate` to the certificate authority (CA) that issued the controller certificate. Helm rendering fails when the Route termination and listener TLS setting do not match these requirements.

The `key`, `certificate`, and `caCertificate` fields configure the certificate that the OpenShift router presents to API clients for edge and re-encrypt Routes. They are distinct from `destinationCACertificate`, which lets the router verify the controller's backend certificate for re-encrypt termination. When the client-facing fields are empty, the Route uses the ingress controller's default certificate.

### Cluster Route values

| Key | Default | Description |
| --- | --- | --- |
| `openshift.route.cluster.enabled` | `true` | Creates a Route to the cluster Service. Disable it when workers do not need an external controller endpoint. |
| `openshift.route.cluster.host` | `""` | Sets the Route hostname. OpenShift generates one when empty. |
| `openshift.route.cluster.annotations` | `{}` | Adds annotations to the Route. |
| `openshift.route.cluster.labels` | `{}` | Adds labels to the Route. |

The chart fixes cluster Route termination to `passthrough` because the listener carries Boundary mutual TLS over TCP. External workers connect to the router on port `443`, not the Service port `9201`. Set the controller's advertised `public_cluster_addr` to `<ROUTE_HOST>:443` when workers use this Route.

### Ops Route values

| Key | Default | Description |
| --- | --- | --- |
| `openshift.route.ops.enabled` | `true` | Creates a Route to the operations Service. |
| `openshift.route.ops.host` | `""` | Sets the Route hostname. OpenShift generates one when empty. |
| `openshift.route.ops.tls.termination` | `reencrypt` | Sets `edge`, `reencrypt`, or `passthrough` termination. |
| `openshift.route.ops.tls.insecureEdgeTerminationPolicy` | `Redirect` | Sets handling for insecure HTTP requests. |
| `openshift.route.ops.tls.key` | `""` | Sets the private key for a client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.ops.tls.certificate` | `""` | Sets the client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.ops.tls.caCertificate` | `""` | Sets the CA certificate chain for the client-facing Route certificate. Omitted for passthrough termination. |
| `openshift.route.ops.tls.destinationCACertificate` | `""` | Sets the CA certificate used to verify the backend for `reencrypt` termination. |
| `openshift.route.ops.annotations` | `{}` | Adds annotations to the Route. |
| `openshift.route.ops.labels` | `{}` | Adds labels to the Route. |

For `edge` termination, set `tls.ops.disabled=true`. For `reencrypt` or `passthrough`, set `tls.ops.disabled=false`. Helm rendering fails when the Route termination and listener TLS setting do not match these requirements. Avoid exposing health and metrics endpoints unless a trusted monitoring path requires the Route.

The ops `key`, `certificate`, and `caCertificate` fields have the same client-facing behavior as their API Route counterparts. The chart omits them for passthrough termination because the router does not terminate the client TLS connection. For reencrypt termination, `destinationCACertificate` verifies the operations listener's backend certificate.

### Service type caveat

Routes add ingress paths to Services. The Routes do not replace Services or change their types. The API Service remains `LoadBalancer` by default even when you enable the API Route. Set `controller.service.api.type=ClusterIP` when you want the Route to be the only external API path. The cluster and operations Services default to `ClusterIP`.

### OpenShift configuration checklist

Before you install or upgrade the controller on OpenShift, confirm the following settings:

- Set `openshift.enabled=true`.
- Decide whether each Route is required, and set exposed Services to `ClusterIP` unless you also want their configured external Service path.
- Match API, cluster, and operations listener ports in `controller.config` to the corresponding Service `targetPort` values.
- Use `<CLUSTER_ROUTE_HOST>:443` as `public_cluster_addr` for workers that connect through the cluster Route.
- Align API and operations listener TLS with each Route termination mode and provide destination CA certificates for `reencrypt` Routes.
- Keep certificate paths under `tls.mountPath`. Probe schemes derive from `tls.ops.disabled` and are not independently configurable.
- Ensure the referenced Secrets contain the keys needed by the rendered HCL and the enabled bootstrap Job.
- Confirm that the ServiceAccount can pull the Red Hat image and that its SCC admits the OpenShift security contexts.
- Check project `ResourceQuota` and `LimitRange` policies for the Deployment and hook Jobs.

### OpenShift troubleshooting

#### Controller pods fail admission

An `unable to validate against any security context constraint` error means the pod requests settings that no SCC allows. Confirm that `openshift.enabled=true`, remove pinned `runAsUser`, `runAsGroup`, and `fsGroup` values, and verify the SCC assigned to the controller ServiceAccount.

#### Controller image pulls fail

Confirm that the pull Secret contains credentials for `registry.connect.redhat.com` and is present in `imagePullSecrets` or linked to the controller ServiceAccount. An explicit `image.repository` or `image.tag` overrides the Red Hat defaults.

#### Routes return TLS errors

Confirm that listener TLS matches the Route termination mode. For `reencrypt`, verify that `destinationCACertificate` contains the CA that issued the backend certificate. Inspect the Route with `oc describe route ROUTE_NAME --namespace PROJECT_NAME`.

#### Workers cannot register through the cluster Route

Confirm that the cluster Route is enabled, uses its fixed `passthrough` termination, and is reachable on port `443`. Set `public_cluster_addr` to the Route hostname and port `443`.
