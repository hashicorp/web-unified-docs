For worker-led registration, install the worker without a controller-generated activation token. The worker generates identity material at startup and writes registration information to the pod logs. For more information, see [Worker-led registration](/boundary/docs/workers/registration/worker-led).

Save the following complete HCL and values as `worker-values.yaml`. Worker-led registration requires persistent auth storage at `/var/lib/boundary`:

```yaml
worker:
  config: |
    disable_mlock = true

    listener "tcp" {
      address = "0.0.0.0:9202"
      purpose = "proxy"
    }

    listener "tcp" {
      address       = "0.0.0.0:9203"
      purpose       = "ops"
      tls_disable   = "{{ .Values.tls.ops.disabled }}"
      tls_cert_file = "{{ .Values.tls.mountPath }}/tls.crt"
      tls_key_file  = "{{ .Values.tls.mountPath }}/tls.key"
    }

    worker {
      initial_upstreams = ["boundary-controller-cluster:9201"]
      auth_storage_path = "/var/lib/boundary"

      tags {
        type = ["worker", "worker-led"]
      }
    }

    events {
      audit_enabled        = true
      sysevents_enabled    = true
      observations_enabled = true
      sink "stderr" {
        name        = "all-events"
        event_types = ["*"]
        format      = "cloudevents-json"
      }
    }
  persistence:
    authStorage:
      enabled: true
      size: 1Gi
      path: /var/lib/boundary
```

Install the worker Helm chart:

```shell-session
$ helm install boundary-worker hashicorp/boundary-worker \
  --namespace boundary \
  --values worker-values.yaml \
  --wait
```

The typical workflow is as follows:

1. Install the worker chart with worker-led registration settings in `worker.config`.
2. Read the worker pod logs.
3. Register or authorize the emitted worker registration information with Boundary.
4. Confirm the worker becomes active.
