## Boundary runtime configuration

The `controller.config` contains the Boundary controller HCL. The chart writes the HCL values into a ConfigMap and mounts it at `/etc/boundary/controller.hcl`.


The chart does not fully validate Boundary controller semantics. You are responsible for configuring valid listeners, database settings, cluster addresses, key management system (KMS) stanzas, rate limits, and event sinks.

The chart performs these targeted checks:

- An API listener exists. An operations listener also exists when `tls.ops.disabled=false`.
- API and operations listener `tls_disable` settings align with `tls.api.disabled` and `tls.ops.disabled`.
- TLS-enabled API and operations listeners use `tls_cert_file` and `tls_key_file` paths under `tls.mountPath`.
- Authenticated Encryption with Associated Data (AEAD) key management system (KMS) keys do not use unsupported `env://BOUNDARY_KMS_*` references.
- Secret-backed database, migration, and license fields use the chart's environment variable names or names declared in `extraEnv`.
- The referenced Secret contains the keys required by the rendered configuration and enabled bootstrap Job when `secretRefs.validateExisting=true`.
- Database migrations run with `controller.replicas=0`, and a repair version is set only when migration is enabled.

## Kubernetes infrastructure configuration

Kubernetes-specific values control the Deployment, Services, ConfigMap, Job hooks, security contexts, ServiceAccount, and scheduling options. These values do not replace or generate the Boundary runtime HCL.

For example, if you change `controller.service.api.targetPort` to `9220`, you must also update the API listener port in the `controller.config`.

Refer to the [configuration alignment checklist](#configuration-alignment-checklist) before you finalize any changes.

The following sections describe the available Helm values grouped by function. Each table lists the key, default value, and a description.

## Naming and namespace values

| Key | Default | Description |
| --- | --- | --- |
| `nameOverride` | `""` | Overrides the chart-generated resource base name |
| `fullnameOverride` | `""` | Fully overrides the chart-generated resource name |
| `namespace` | `""` | Overrides the namespace the chart renders namespaced resources into. An empty value uses the Helm release namespace. |

## Image values

| Key | Default | Description |
| --- | --- | --- |
| `image.repository` | `""` | Image repository override. An empty value uses `hashicorp/boundary-enterprise`. |
| `image.tag` | `""` | Image tag override. An empty value uses the chart application version, `1.0.2-ent` for chart `0.2.0`. |
| `image.pullPolicy` | `IfNotPresent` | Kubernetes image pull policy |
| `imagePullSecrets` | `[]` | Optional image pull secrets for private registries |

## TLS values

| Key | Default | Description |
| --- | --- | --- |
| `tls.api.disabled` | `false` | Disables TLS for the API listener when `true`. |
| `tls.ops.disabled` | `false` | Disables TLS for the operations listener when `true`. |
| `tls.secretName` | `boundary-controller-tls` | Name of the Kubernetes TLS Secret mounted when TLS is enabled |
| `tls.mountPath` | `/etc/boundary/tls` | Container path where the TLS Secret is mounted |

You can configure API and operations TLS independently. The chart mounts the TLS Secret when either listener has TLS enabled. Keep each listener's `tls_disable` setting aligned with its corresponding chart value and keep certificate paths aligned with `tls.mountPath`. The chart checks the paths but does not validate certificate contents, trust, expiration, or subject alternative names (SANs).
