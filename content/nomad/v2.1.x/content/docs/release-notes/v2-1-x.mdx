# Nomad 2.1.x release notes

@include '../../../global/partials/version-eol-chart.mdx'

## 2.1.0

Release Date: 27 October 2026

### Release highlights

Nomad 2.1.0 includes the following features and improvements.

#### Batch job queue

@include '../../../global/partials/status/experimental.mdx'

You can configure an experimental batch job queue on a node pool with the
[`batch_queue`](/nomad/docs/other-specifications/node-pool#batch_queue-parameters)
block. The queue holds the batch jobs that you register in the node pool and
sends them to the scheduler one at a time. The queue waits for Nomad to place
each job before it sends the next one.

A first in, first out (FIFO) queue schedules jobs in the order that you
register them. A dynamic priority queue recalculates each job's priority from
the job's age, the job's resource size, and how much of the node pool's
resources each tenant uses. You identify tenants by namespace or by a metadata
key.

Use the [`nomad queue`](/nomad/commands/queue) commands to view the jobs in
a queue and the status of a dynamic priority queue. Refer to [Batch job
queue](/nomad/docs/concepts/scheduling/batch-job-queue) to learn how the queue
orders jobs, and [Queue batch jobs](/nomad/docs/govern/queue-batch-jobs) to
configure one.

#### Optional object type attributes in input variables

Job specification input variables support the `optional()` modifier in
object type constraints. When you omit an optional attribute, Nomad fills it
with the default value that you declare in `optional()` instead of returning
an error. Refer to [Optional object type
attributes](/nomad/docs/reference/hcl2/variables#optional-object-type-attributes)
for details.

#### New `nomad operator snapshot filter` command

The `nomad operator snapshot filter` command removes selected entries from an
existing snapshot file and writes the result to a copy. Use it to remove
objects from a snapshot before you restore it to a cluster, or to remove a
large number of pending evaluations when you recover a cluster from an outage.
Refer to the [`nomad operator snapshot filter` command
reference](/nomad/commands/operator/snapshot/filter) for details.

#### TLS verification uses the Go standard library

Nomad now uses the Go standard library to verify TLS certificates during
agent-to-agent connections. The error messages for TLS handshake failures
might differ from earlier versions, so update any log alerts or scripts that
match on those messages.

### Breaking changes

Review the following changes before you upgrade to Nomad 2.1.0.

#### Server join requires the `agent:write` permission

When ACLs are enabled, the `nomad server join` command and the [Join
Agent](/nomad/api-docs/agent#join-agent) API require a token with the
`agent:write` permission.

#### Removed deprecated server join configurations

We removed the deprecated server configuration parameters `retry_join`,
`retry_interval`, `retry_max`, and `start_join` from the `server` block. A
server agent that still sets these parameters fails to start. Set them in the
[`server_join`](/nomad/docs/configuration/server_join) block instead.

### Deprecations

Nomad 2.1.0 deprecates or removes support for the following.

#### Deprecated resource fields on the Allocation API

The `Resources` and `TaskResources` fields on the Go API's `Allocation` struct
are deprecated. Nomad servers do not populate these fields. Use the
`AllocatedResources` field instead.

The HTTP API no longer returns the `Resources`, `SharedResources`, and
`TaskResources` fields in allocation responses. Read an allocation's resources
from the `AllocatedResources` field instead.

#### Client state databases older than Nomad 0.9 are not supported

Nomad clients do not support state databases from Nomad versions older than
0.9. When you restore a client state database from a backup older than Nomad
0.9, the client fails to start.

Refer to the [Nomad 2.1.0 upgrade-specific
documentation](/nomad/docs/upgrade/upgrade-specific#nomad-210) for details.
