# Batch Job Queue HTTP API

The `/queue` endpoints inspect the batch job queue of a node pool.
Refer to [Batch job queue](/nomad/docs/concepts/scheduling/batch-job-queue) for
details about how queues work.

## List Queued Jobs

This endpoint lists the jobs in the batch job queue of a node pool. The response
includes jobs that are waiting in the queue and the job that the queue sent to
the scheduler.

| Method | Path             | Produces           |
| ------ | ---------------- | ------------------ |
| `GET`  | `/v1/queue/jobs` | `application/json` |

The following table shows this endpoint's support for
[blocking queries](/nomad/api-docs#blocking-queries) and
[required ACLs](/nomad/api-docs#acls).

| Blocking Queries | ACL Required          |
| ---------------- | --------------------- |
| `NO`             | `namespace:list-jobs` |

The response only includes jobs in namespaces where the token has the
`list-jobs` capability.

### Parameters

- `node_pool` `(string: "default")` - Specifies the node pool whose queue to
  list. Specify this as a query string parameter.

- `sort` `(string: "default")` - Specifies the order of the jobs in the
  response. Set to `priority` to return jobs in queue order, which is the order
  that the queue sends them to the scheduler. Any other value returns jobs
  sorted by job ID. Specify this as a query string parameter.

- `next_token` `(string: "")` - This endpoint supports paging. The `next_token`
  parameter accepts a string that identifies the next expected job. Get this
  value from the `X-Nomad-NextToken` header of the last response.

- `per_page` `(int: 0)` - Specifies a maximum number of jobs to return for this
  request. If omitted, Nomad does not paginate the response. To fetch additional
  pages, use the value of the `X-Nomad-NextToken` header of the last response as
  the `next_token` of the next request.

### Response

The `Type` field contains the queue type of the node pool, which is
`dynamic_priority`, `fifo`, or `passthrough`. A node pool without a queue
returns `passthrough` and an empty `Workloads` list.

Each object in `Workloads` contains the following fields for all queue types.

- `JobID` is the ID of the job.
- `Namespace` is the namespace of the job.
- `Status` is `queued` for a job that is waiting in the queue, `placing` for the
  job that the queue sent to the scheduler, or `blocked` with a reason for a job
  that the scheduler cannot place because of its constraints.
- `Position` is the job's position in the queue. The job that the queue sent to
  the scheduler has position `0`.
- `CreatedAt` is the creation time of the job's evaluation, in nanoseconds since
  the Unix epoch.
- `CreateIndex` is the Raft index at which Nomad created the job's evaluation.

For a `dynamic_priority` queue, each object also contains the following fields.

- `Tenant` is the tenant of the job.
- `AdjustedPriority` is the priority that the queue uses to order the job.
- `BasePriority` is the job's priority.
- `UsageAdjustment`, `AgeAdjustment`, `CpuAdjustment`, and `MemoryAdjustment`
  are the adjustments that the queue adds to the base priority. Refer to
  [Adjusted
  priority](/nomad/docs/concepts/scheduling/batch-job-queue#adjusted-priority)
  for details.

## List Queue Tenants

This endpoint lists the tenants in the dynamic priority batch job queue of a node
pool and their recent resource usage.

| Method | Path                | Produces           |
| ------ | ------------------- | ------------------ |
| `GET`  | `/v1/queue/tenants` | `application/json` |

The following table shows this endpoint's support for
[blocking queries](/nomad/api-docs#blocking-queries) and
[required ACLs](/nomad/api-docs#acls).

| Blocking Queries | ACL Required    |
| ---------------- | --------------- |
| `NO`             | `operator:read` |

### Parameters

- `node_pool` `(string: "default")` - Specifies the node pool whose queue to
  inspect. Specify this as a query string parameter.

### Response

The `Type` field contains the queue type of the node pool. Only a
`dynamic_priority` queue returns tenants. Other queue types return `null` for
`Tenants`.

Each object in `Tenants` contains the following fields.

- `TenantID` is the tenant, which is a namespace or a job metadata value
  depending on the queue's `tenant_type`.
- `TenantUsage` is the tenant's recent `cpu` usage in MHz and `memory` usage in
  MB. Usage decays according to the queue's `half_life` parameter.
- `TotalUsage` is the recent `cpu` and `memory` usage of all tenants in the
  queue.
- `PercentageUsed` is the tenant's share of the combined CPU and memory usage of
  all tenants, as a whole number percentage.

### Sample Request

```shell-session
$ nomad operator api '/v1/queue/tenants?node_pool=batch'
```
