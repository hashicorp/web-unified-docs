# Nomad Autoscaler release notes

The Nomad Autoscaler documentation refers to the latest version.

## 0.6.0 release highlights

**Release Date:** September 28, 2026

### New Instana APM plugin

The `instana` APM plugin queries infrastructure metrics from Instana.
Authenticate with the `api_token` configuration key or the `INSTANA_API_TOKEN`
environment variable. Refer to [the Instana APM plugin
documentation](/nomad/tools/autoscaling/plugins/apm/instana) for more
information.

### Nomad APM plugin groups nodes by more pool identifiers

Node pool queries in the Nomad APM plugin now group nodes by `datacenter`,
`node_pool`, or a combination of pool identifiers. Previous releases supported
only `node_class`. Refer to [the Nomad APM plugin client node
options](/nomad/tools/autoscaling/plugins/apm/nomad#policy-configuration-options-client-nodes)
for details.

### File-based scaling policies support `jsonencode`

File-based scaling policies accept the `jsonencode` function in fields such as
`check.query`. Write complex JSON queries as native HCL objects instead of
escaped JSON strings. Refer to [the policy `check`
options](/nomad/tools/autoscaling/policy#check-options) for details.

### Bug fixes

- **Policy evaluation recovery.** After the policy manager recovers from an
  unrecoverable source error, the autoscaler now recreates policy handlers for
  unchanged policies. Previously, existing policies stopped being evaluated
  until you updated them.

- **Safer node termination after draining.** After a node drain completes, the
  autoscaler now waits until all tasks on the node stop before it terminates
  the instance. Previously, the autoscaler could terminate the instance
  immediately after the drain, which interrupted in-progress lifecycle tasks.

### Changelog

Refer to the [GitHub v0.6.0
changelog](https://github.com/hashicorp/nomad-autoscaler/releases/tag/v0.6.0)
for complete release details.

## 0.5.0 release highlights

**Release Date:** May 18, 2026

### Nomad Autoscaler supports schedule-based autoscaling at policy and check levels 

You can define recurring windows with `start + end` or `start +
duration` using strict 5-field cron expressions evaluated in UTC. Refer to the
following for details:
  - [Schedule-based autoscaling](/nomad/tools/autoscaling/schedule)  
  - [Policy schedule options](/nomad/tools/autoscaling/policy#schedule-options) 

### Policy evaluation checks 

Checks that use the `fixed-value` strategy no longer require APM `source` or
`query` configuration. Refer to [the policy evaluation scheduled checks
documentation](/nomad/tools/autoscaling/concepts/policy-eval/checks#scheduled-checks)
for more information.

### Nomad agent configuration now accepts multiple namespaces

The [`nomad` agent configuration block](/nomad/tools/autoscaling/agent/nomad)
and [the `-nomad-namespace` CLI
flag](/nomad/tools/autoscaling/cli#nomad-namespace) now accept multiple
namespaces. Use a list to monitor policies across several namespaces, or use `*`
to monitor all namespaces.

### New InfluxDB APM plugin

The plugin supports InfluxDB 1.x and InfluxQL queries. You can authenticate with
HTTP basic authentication or JWT bearer authentication using a shared secret.
Refer to [the InfluxDB APM plugin
documentation](/nomad/tools/autoscaling/plugins/apm/influxdb) for more
information.

### Prometheus APM Plugin enhancement

The Prometheus APM plugin supports `query_window = "instant"` to evaluate a
check at a single point in time instead of over a range. Refer to [Prometheus
APM plugin](/nomad/tools/autoscaling/plugins/apm/prometheus) for details.

### Changelog

Refer to the [GitHub v0.5.0
changelog](https://github.com/hashicorp/nomad-autoscaler/releases/tag/v0.5.0)
for complete release details.
