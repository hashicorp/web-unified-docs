# vSphere Target Plugin

The `vsphere-target` target plugin allows for the scaling of the Nomad cluster
clients via cloning and destroying VMware vSphere virtual machines. This is an
enterprise-only built-in plugin.

## Agent Configuration Options

The plugin connects to vCenter using the VMware govmomi SDK and authenticates
via username and password against the vCenter SOAP API.

Credentials should be injected into the configuration via a template rather
than as environment variables. This ensures the credentials are passed only to
the plugin, rather than being available for all plugins and the agent process.

```hcl
plugin "vsphere-target" {
  driver = "vsphere-target"

  config = {
    vcenter_url        = "https://vcenter.example.com/sdk"
    username           = "svc-autoscaler@vsphere.local"
    password           = "REPLACE_WITH_SECRET"
    vsphere_datacenter = "Datacenter"
  }
}
```

- `vcenter_url` `(string: <required>)` - The full URL of the vCenter Server SDK
  endpoint (e.g. `https://vcenter.example.com/sdk`).

- `username` `(string: <required>)` - The vCenter service account username.

- `password` `(string: <required>)` - The vCenter service account password.

- `vsphere_datacenter` `(string: <required>)` - The name of the vCenter
  datacenter that contains the target VMs.

- `insecure_skip_verify` `(bool: false)` - Skips TLS certificate verification
  for the vCenter endpoint. Should only be used in non-production environments.

### Nomad ACL

When using a Nomad cluster with ACLs enabled, the plugin will require an ACL
token which provides the following permissions:

```hcl
node {
  policy = "write"
}
```

## Policy Configuration Options

```hcl
check "vsphere-allocated-cpu" {
  # ...
  target "vsphere-target" {
    vm_template               = "DC0/vm/templates/nomad-worker"
    vm_folder                 = "DC0/vm/nomad-workers"
    resource_pool             = "DC0/host/Cluster/Resources/nomad"
    vm_name_prefix            = "nomad-worker"
    node_class                = "hashistack"
    node_drain_deadline       = "5m"
    node_purge                = "true"
    operation_timeout         = "30m"
    node_registration_timeout = "10m"
    graceful_shutdown_timeout = "5m"
  }
  # ...
}
```

- `vm_template` `(string: <required>)` - Inventory path of the vSphere VM
  template to clone from. The object must be marked as a template in vCenter.

- `vm_folder` `(string: <required>)` - Inventory path of the VM folder where
  cloned VMs will be placed.

- `resource_pool` `(string: <required>)` - Inventory path of the resource pool
  cloned VMs are assigned to.

- `vm_name_prefix` `(string: <required>)` - Prefix for provisioned VM names. A
  random 8-character suffix is appended automatically (e.g. `worker-a1b2c3d4`).

- `datacenter` `(string: "")` - The Nomad client [datacenter][nomad_datacenter]
  identifier used to group nodes into a pool of resource.

- `node_class` `(string: "")` - The Nomad [client node class][nomad_node_class]
  identifier used to group nodes into a pool of resource.

- `node_pool` `(string: "")` - The Nomad [client node pool][nomad_node_pool]
  identifier used to group nodes into a pool of resource.

- `node_drain_deadline` `(duration: "15m")` The Nomad [drain
  deadline][nomad_node_drain_deadline] to use when performing node draining
  actions. **Note that the default value for this setting differs from Nomad's
  default of 1h.**

- `node_drain_ignore_system_jobs` `(bool: "false")` A boolean flag used to
  control if system jobs should be stopped when performing node draining
  actions.

- `node_purge` `(bool: "false")` A boolean flag to determine whether Nomad
  clients should be [purged][nomad_node_purge] when performing scale in
  actions.

- `node_selector_strategy` `(string: "least_busy")` The strategy to use when
  selecting nodes for termination. Refer to the [node selector
  strategy][node_selector_strategy] documentation for more information.

- `operation_timeout` `(duration: "30m")` - Maximum time allowed for an entire
  scale operation.

- `node_registration_timeout` `(duration: "10m")` - How long to wait for newly
  cloned VMs to register as ready Nomad clients after power-on.

- `graceful_shutdown_timeout` `(duration: "5m")` - How long to wait for a
  graceful guest OS shutdown before forcing a hard power-off on scale in.
