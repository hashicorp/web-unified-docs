- **Run two Vault Enterprise clusters**. Initialize and unseal a primary cluster
  and a secondary cluster. Both clusters need a storage backend that supports
  transactional updates, such as integrated storage. The secondary can run the
  same Vault version as the primary or a newer one.

- **Back up the secondary cluster**. Enabling replication on the secondary
  deletes all existing data on it, including its root token, auth methods, and
  secrets.

- **Open the replication ports**. Allow TCP traffic in both directions between
  the clusters on the cluster port, 8201 by default. The secondary also needs
  the primary's API port, 8200 by default, unless you activate it with a public
  key. Refer to [Shared design
  considerations](/vault/docs/enterprise/replication#shared-design-considerations).

- **Set the cluster addresses**. Set `api_addr` and `cluster_addr` on every
  node. Refer to the [high availability
  parameters](/vault/docs/configuration#high-availability-parameters). If a
  load balancer fronts the primary's cluster port, it must pass TCP through
  without terminating TLS and route to the active node.

- **Choose an activation method**. Decide whether the secondary unwraps the
  activation token from the primary's API or receives a token encrypted with
  its own public key. Refer to [Activation
  methods](/vault/docs/enterprise/replication#activation-methods).
