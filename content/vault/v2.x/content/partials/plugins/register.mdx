### Register an official plugin from a versioned `.zip` artifact

Use the versioned release artifact for official Enterprise plugins. Extract the
artifact into the configured `plugin_directory` on every Vault node. Keep the
extracted directory name identical to the archive name without the `.zip`
extension. Official community plugins also support this artifact workflow on
supported Vault versions. Register the plugin with `-version`. Do not provide
`-sha256` for an official Enterprise plugin; Vault returns an error if you
provide it.

For example, extract
`vault-plugin-secrets-keymgmt_0.16.0+ent_linux_amd64.zip` to
`<plugin_directory>/vault-plugin-secrets-keymgmt_0.16.0+ent_linux_amd64/`.

<Tabs>

<Tab heading="CLI" group="cli">

```shell-session
$ vault plugin register \
    -version="v0.16.0+ent" \
    -args=--with-glibc,--with-curl-bindings \
    secret \
    vault-plugin-secrets-keymgmt

Success! Registered plugin: vault-plugin-secrets-keymgmt
```

</Tab>

<Tab heading="API" group="api">

Send the plugin version in the request body. Do not include a `sha256` field.

```shell-session
$ curl \
    --request POST \
    --header "X-Vault-Token: ${VAULT_TOKEN}" \
    --data '{"version":"v0.16.0+ent"}' \
    ${VAULT_ADDR}/v1/sys/plugins/catalog/secret/vault-plugin-secrets-keymgmt
```

</Tab>

</Tabs>

After registration, verify that the plugin appears in the catalog.

<Tabs>

<Tab heading="CLI" group="cli">

```shell-session
$ vault plugin list -detailed database
```

</Tab>

<Tab heading="API" group="api">

```shell-session
$ curl \
    --header "X-Vault-Token: ${VAULT_TOKEN}" \
    ${VAULT_ADDR}/v1/sys/plugins/catalog \
    | jq '.data.detailed | .[] | select(.name == "vault-plugin-secrets-keymgmt")'
```

</Tab>

</Tabs>

### Register a community or custom plugin from a binary

Use this method for a community or custom plugin binary. Calculate the binary's
SHA-256 checksum and provide it with `-sha256`. The CLI uses the plugin name as
the command by default; set `-command` when the executable name differs from the
catalog name. Official Enterprise plugins must use the versioned `.zip` artifact
method above; binary registration with `-sha256` is not supported for them.

<Tabs>

<Tab heading="CLI" group="cli">

Calculate the checksum, then register the binary. The `-command` value is the
binary name relative to `plugin_directory`.

```shell-session
$ PLUGIN_SHA=$(sha256sum ./my-custom-plugin | awk '{print $1}')
$ vault plugin register \
    -command="my-custom-plugin" \
    -sha256="${PLUGIN_SHA}" \
    -version="v1.0.1" \
    secret \
    my-custom-plugin

Success! Registered plugin: my-custom-plugin
```

</Tab>

<Tab heading="API" group="api">

Include `sha256`, `command`, and, if available, `version` in the request body.

```shell-session
$ PLUGIN_SHA=$(sha256sum ./my-custom-plugin | awk '{print $1}')
$ cat <<EOF > data.json
{
  "sha256": "${PLUGIN_SHA}",
  "command": "my-custom-plugin",
  "version": "v1.0.1"
}
EOF
$ curl \
    --request POST \
    --header "X-Vault-Token: ${VAULT_TOKEN}" \
    --data @data.json \
    ${VAULT_ADDR}/v1/sys/plugins/catalog/secret/my-custom-plugin
```

</Tab>

</Tabs>
