# Configure Auth0 for agent IAM

@include 'alerts/enterprise-and-hcp.mdx'

Configure users and OIDC applications in Auth0 to use with Vault Enterprise
agentic IAM.


## Before you start

- **You must have an [Auth0](https://auth0.com/) Enterprise plan tenant** with
  permissions to create an Application, an API, a user, and enable/remove Rich
  Authorization Request (RAR) and Pushed Authorization Requests (PAR). Auth0
  Enterprise plan or higher is required for RAR and PAR support. Refer to [Auth0
  pricing](https://auth0.com/pricing) for feature availability by plan tier.

- **You must have the [`oauth2c`](https://github.com/SecureAuthCorp/oauth2c) CLI**.
  You need `oauth2c` installed and in your system `PATH` to interact with OAuth
  2.0 authorization servers.

Vault](/vault/tutorials/enterprise/secure-agent-permissions-with-vault) tutorial

## Step 1: Enable pushed authorization requests

Enable Pushed Authorization Requests (PAR) tenant-wide. PAR (defined in [RFC
9126](https://datatracker.ietf.org/doc/html/rfc9126)) is required to attach RAR
claims because standard authorization requests cannot carry complex JSON
structures.

1. Log in to your Auth0 dashboard.

1. Navigate to **Settings** > **Advanced**.

1. Locate **Allow Pushed Authorization Requests (PAR)** and switch the toggle
   **ON**. Auth0 saves the setting automatically.

## Step 2: Create an API

1. Navigate to **Applications** > **APIs**.

1. Click **Create API**.

1. In the **Name** field, enter a name value (for example, `vault-api`).

1. In the **Identifier** field, enter your Vault cluster's API address. The
   identifier value becomes the JWT `aud` claim.

1. For **JSON Web Token (JWT) Profile**, select **RFC 9068**.

1. Scroll down and click **Create**.

1. Click the **Settings**.

1. Scroll down to **RBAC Settings**.

1. Click the toggle to switch on **Enable RBAC**.

1. Click the toggle to switch on **Add Permissions in the Access Token**.

1. Click **Save**.

## Step 3: Create an application

1. Navigate to **Applications** > **Applications**, then click
   **Create Application**.

1. In the **Name** field, enter the application name and select the application type.

1. Click **Create**.

1. Click **Settings**. You can find the **Client ID** and **Client Secret** of
   your application.

1. Scroll to **Application URIs** section. In the **Allowed Callback URLs**
   field, enter the `oauth2c` callback URL.

1. Scroll to the **Authorization Requests** section and turn **ON**
   **Require Pushed Authorization Requests (PAR)** so PAR is mandatory for this
   application.

1. Click **Advanced Settings**.

1. Click **OAuth**.

1. In the **Allowed APPs/APIs** field, enter the Vault API address (for example,
   `https://<vault-addr>:8200/v1`)

1. Open the **Grant Types** tab and check **Authorization Code**.

1. Open the **Endpoints** tab and record both the **OAuth Authorization URL**
   and the **JSON Web Key Set URL** values for use later.

1. Click **Save**.

## Step 4: Register the RAR authorization details type

Rich Authorization Requests (RAR) require Auth0 to recognize the custom
authorization details `type` that Vault expects (`vault:path_access`). With PAR
enabled, register an authorization details type named `vault:path_access` for
your tenant.

1. Navigate to **Auth0 Dashboard** > **Applications** > **APIs**, and select the API you created.

1. Click **Permissions**.

1. Under **Add an Authorization Details type** in the **Type** field, enter
   `vault:path_access`.

1. Click **+Add** and the authorization details type setting gets
   automatically saved.

## Step 5: Grant application access

With the API and application both created, you need to grant client access from
the API to the application.

1. Navigate to **Auth0 Dashboard** > **Applications** > **APIs**, and select the API you created.

1. Click **Application Access**.

1. Find your application, and click **Edit**.

1. Click **Grant Access**.

1. Click the **Always grant all permissions** checkbox.

1. Click **Save**.

## Step 6: Allow the application to request the RAR type

The **Always grant all permissions** checkbox only grants OAuth scopes.
It does not allow the application to request the `vault:path_access`
authorization details (RAR) type.

Whether an application may request a registered `authorization_details` type is
controlled separately by the API's User-Delegated Access policy:

- **All apps allowed** (`allow_all`): any application may request every
  `authorization_details` type registered on the API. No per-application
  configuration is required, and you can set this entirely in the Dashboard.

- **Per-app authorization** (`require_client_grant`): each `authorization_details`
  type must be explicitly listed in the application's client grant under
  `authorization_details_types`. This field is **not** exposed in the Dashboard
  and can only be set through the Auth0 Management API.

<Tabs>
<Tab heading="All apps allowed">

To set the policy to **All apps allowed**:

1. Navigate to **Applications** > **APIs** and click **vault-api**.

1. Click the **Settings** tab and scroll to **Application Access Policy**.

1. Set **User-Delegated Access** to **All apps allowed**.

1. Click **Save**.

</Tab>
<Tab heading="Per-app authorization">

If you prefer to keep **Per-app authorization** (least privilege), leave the
policy unchanged and instead add the RAR type to the client grant using the
Management API. Find the grant id with
`GET /api/v2/client-grants?client_id=${APP_CLIENT_ID}`, then patch it:

```shell-session
$ curl -X PATCH "https://${APP_DOMAIN}/api/v2/client-grants/<GRANT_ID>" \
    -H "Authorization: Bearer ${MGMT_TOKEN}" \
    -H "Content-Type: application/json" \
    -d '{"authorization_details_types":["vault:path_access"]}'
```

The `authorization_details_types` field applies only to user-delegated access
flows.

</Tab>
</Tabs>

## Step 7: Create an agent user

1. Navigate to **User Management** > **Users**.

1. Click **Create User** and select **Create via UI** or **Create via JSON**.

1. Enter the **Email** and **Password**.

1. Click **Create**.

1. On the user page, click **Edit** next to **Email**, and set the email as
   verified.

## Step 8: Capture a baseline token

Export the Auth0 values you recorded, then run `oauth2c` to confirm the trust
and to capture the `iss` and `sub` claims you need for the Vault profile and
entity aliases.

1. Save the Auth0 configuration values as environment variables. Replace the
   placeholders with your actual values from the Auth0 application settings.

    ```shell-session
    $ export APP_AUTH_URL="https://YOUR_TENANT.us.auth0.com/authorize" \
        APP_CLIENT_ID="<application client id>" \
        APP_CLIENT_SECRET="<application client secret>" \
        APP_JWKS_URI="https://YOUR_TENANT.us.auth0.com/.well-known/jwks.json"
    ```

    The export command does not produce any output.

1. Save the Vault address in `AUDIENCE_ADDR` environment variable. You will use
   it to request the correct audience in the access token.

    ```shell-session
    $ export AUDIENCE_ADDR=${VAULT_ADDR}/v1
    ```

1. Generate an access token using the OAuth 2.0 authorization code flow with
   PKCE and PAR.

    ```shell-session
    $ oauth2c "${APP_AUTH_URL}" \
        --pkce \
        --par \
        --client-id "${APP_CLIENT_ID}" \
        --client-secret "${APP_CLIENT_SECRET}" \
        --response-types code \
        --response-mode query \
        --grant-type authorization_code \
        --audience ${AUDIENCE_ADDR} \
        --auth-method client_secret_basic
    ```

    <Note>

    You must request the audience (`--audience https://<vault_addr>:8200/v1`) to
    receive a signed JWT. Without it, Auth0 returns an opaque token that Vault
    cannot validate.

    </Note>

    `oauth2c` opens a browser. Sign in with the email address and password you
    set in the **create an agent user** section. After successful sign-in, the
    terminal prints a success message along with the decoded access token:

    <CodeBlockConfig hideClipboard>

    ```plaintext
    SUCCESS  Exchanged authorization code for access token
    ```

    </CodeBlockConfig>

    Example token values:

    <CodeBlockConfig hideClipboard>

    ```json
    {
      "aud": "https://localhost:8200/v1",
      "client_id": "EBYeLHzuLqSeyUYLY7EC3hqRgvaiS9Dv",
      "exp": 1782402664,
      "iat": 1782316264,
      "iss": "https://hashicups-dev.us.auth0.com/",
      "jti": "baFC3mowpruhSr1JdDRhbJ",
      "permissions": [],
      "sub": "auth0|c0ff33a2dc1f8e9de0dd95d7"
    }
    ```

    </CodeBlockConfig>

1. Record the `iss` and `sub` values and export them. The `sub` value contains
   a pipe character, so wrap it in single quotes so the shell doesn't use it.

    For example:

    ```shell-session
    $ export APP_ISS_URL="https://hashicups-dev.us.auth0.com/" \
        APP_JWT_SUB='auth0|c0ff33a2dc1f8e9de0dd95d7'
    ```

    This `sub` is the agent's external identity. In the **create the subject and
    actor entities and aliases** step you will create a separate external
    identity for Danielle the human subject.


## Step 9: Save your provider information

Confirm your subject and actor details from Auth0. To configure agentic IAM,
you must have the following information:

| Value             | Environmental variable | Description                                                                                       |
| ----------------- | ---------------------- | ------------------------------------------------------------------------------------------------- |
| Authorization URL | `APP_AUTH_URL`         | Authorization URL of the application: `https://YOUR_TENANT.us.auth0.com/authorize`                |
| Issuer URL         | `APP_ISS_URL`          | URL identifying the authentication entry point: `https://APP_NAME.us.auth0.com/`                   |
| JWT subject       | `APP_JWT_SUB`          | The JWT claim to use as the user identifier                                                       |
| JWKS URL          | `APP_JWKS_URI`         | URI to fetch public keys in JWKS format: `https://YOUR_TENANT.us.auth0.com/.well-known/jwks.json` |
| Client ID         | `APP_CLIENT_ID`        | Client ID of the application you registered in Auth0                                              |
| Client secret     | `APP_CLIENT_SECRET`    | Client secret associated with the application                                                     |
| Audience address  | `AUDIENCE_ADDR`        | Vault cluster address including the API version, `/v1`                                            |
| Domain address    | `APP_DOMAIN`           | Domain of the application you registered in Auth0                                                 |

Set the following environment variables to make Vault configuration more
convenient:

```shell-session
$ export VAULT_ADDR="<your_vault_server_url>" \
      APP_AUTH_URL="<app_auth_url>" \
      APP_CLIENT_ID="<app_client_id>" \
      APP_CLIENT_SECRET="<app_client_secret>" \
      APP_JWKS_URI="<app_jwks_url>" \
      APP_JWT_SUB="<app_jwt_sub>" \
      APP_ISS_URL="<app_iss_url>" \
      AUDIENCE_ADDR="<aud_address>" \
      APP_DOMAIN="<app_domain>"       
```

For example:

<CodeBlockConfig hideClipboard>

```shell-session
$ export VAULT_ADDR="https://127.0.0.1:8200" \
      APP_AUTH_URL="https://abc-123if67e.us.auth0.com/authorize" \
      APP_CLIENT_ID="ABCD...abc" \
      APP_CLIENT_SECRET="000000...000000" \
      APP_JWKS_URI="https://abc-123if67e.us.auth0.com/.well-known/jwks.json" \
      APP_JWT_SUB="auth0|c0ff33a2dc1f8e9de0dd95d7" \
      APP_ISS_URL="https://hashicups-dev.us.auth0.com/" \
      AUDIENCE_ADDR="https://127.0.0.1:8200/v1" \
      APP_DOMAIN="abc-123if67e.auth0.com"      
```

</CodeBlockConfig>
