# OAuth Resource Server HTTP API

@include 'alerts/enterprise-only.mdx'

The `/sys/oauth-resource-server` endpoints provide OAuth Resource Server configuration management and Rich Authorization Request (RAR) type discovery capabilities. These endpoints support:

- OAuth resource server configuration profile management.
- Authorization details type catalog discovery (RFC 9396).
- OAuth protected resource metadata publication (RFC 9728).
- JSON schema retrieval for `authorization_details` validation.

## Configuration profile management

### List OAuth profiles

Fetch all OAuth resource server configuration profile names in the current namespace.

| Method | Path |
| :----- | :--- |
| `LIST` | `/sys/config/oauth-resource-server` |

#### Sample request

```shell-session
$ curl \
    --header "X-Vault-Token: ${VAULT_TOKEN}" \
    --request LIST \
    ${VAULT_ADDR}/v1/sys/config/oauth-resource-server
```

#### Sample response

```json
{
  "data": {
    "keys": ["auth0-prod", "okta-dev", "entra-id"]
  }
}
```

### Create/Update OAuth profile

Create or update an OAuth resource server configuration profile.

| Method | Path |
| :----- | :--- |
| `POST`/`PUT` | `/sys/config/oauth-resource-server/:name` |

#### Parameters

- `name` `(string: <required>)` - The name of the OAuth resource server configuration profile. Specified in the URL.

- `issuer_id` `(string: <required>)` - The issuer identifier (`iss` claim) to validate against. Must be a valid URL. Required for create operations.

- `use_jwks` `(boolean: true)` - If true, use JWKS URI for public key validation. If false, use static public keys.

- `jwks_uri` `(string: "")` - The JWKS URI to fetch public keys from. Required when `use_jwks=true`. Must be a valid HTTPS URL. Vault only allows HTTP URLs for development use.

- `jwks_ca_pem` `(string: "")` - Optional PEM-encoded CA certificate for JWKS URI TLS validation. Used when the JWKS endpoint uses a custom CA.

- `public_keys` `(array: [])` - List of static public keys. Required when `use_jwks=false`. Each entry must contain:
  - `key_id` `(string: <required>)` - Key identifier (`kid`).
  - `pem` `(string: <required>)` - PEM-encoded public key or certificate.

- `audiences` `(array: [])` - List of allowed audience values (`aud` claim). If you provide explicit audiences, client requests must match at least one audience in the list.

- `no_default_policy` `(boolean: false)` - If true, JWT-authenticated tokens omit the default policy unless applied elsewhere.

- `optional_authorization_details` `(boolean: false)` - Makes the
  `authorization_details` claim optional for OAuth 2.0 JWTs using the associated
  profile. By default, Vault makes the `authorization_details` claim mandatory
  when an applicable OAuth profile exists.

- `user_claim` `(string: "sub")` - The JWT claim to use as the Vault entity identifier.

- `supported_algorithms` `(array: [])` - List of supported signing algorithms such
  as RS256, ES256, and PS256. Leave `supported_algorithms` empty to allow all
  algorithms supported by the provided keys.

- `jwt_type` `(string: "access_token")` - The JWT type to validate. Must be "access_token" or "transaction_token".

- `clock_skew_leeway` `(integer: 0)` - Clock skew leeway in seconds for time-based claim validation (`exp`, `nbf`, `iat`).

- `enabled` `(boolean: true)` - Makes the profile available for JWT validation.
  Vault ignores disabled profiles during authorization.

#### Sample payload - JWKS

```json
{
  "issuer_id": "https://auth.example.com",
  "audiences": ["vault-api"],
  "use_jwks": true,
  "jwks_uri": "https://auth.example.com/.well-known/jwks.json",
  "user_claim": "sub",
  "jwt_type": "access_token",
  "supported_algorithms": ["RS256", "ES256"],
  "clock_skew_leeway": 60,
  "enabled": true
}
```

#### Sample payload - static keys

```json
{
  "issuer_id": "https://auth.example.com",
  "audiences": ["vault-api"],
  "use_jwks": false,
  "public_keys": [
    {
      "key_id": "key-1",
      "pem": "-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...\n-----END PUBLIC KEY-----"
    }
  ],
  "user_claim": "sub",
  "jwt_type": "access_token"
}
```

#### Sample request

```shell-session
$ curl \
    --header "X-Vault-Token: ${VAULT_TOKEN}" \
    --request POST \
    --data @payload.json \
    ${VAULT_ADDR}/v1/sys/config/oauth-resource-server/my-idp
```

#### Sample response

```json
{
  "warnings": [
    "JWKS URI uses HTTP instead of HTTPS. This is insecure and should only be used in development."
  ]
}
```

## Authorization details type discovery

The following endpoints support OAuth 2.0 Rich Authorization Request (RAR) type
discovery per RFC 9396 and RFC 9728.

### List authorization details types

Fetch all supported `authorization_details` type identifiers.

| Method | Path |
| :----- | :--- |
| `LIST` | `/sys/oauth-resource-server/authorization-details-types` |

#### Sample request

```shell-session
$ curl \
    --request LIST \
    ${VAULT_ADDR}/v1/sys/oauth-resource-server/authorization-details-types
```

#### Sample response

```json
{
  "data": {
    "keys": ["vault:path_access"]
  }
}
```

### Read authorization details type catalog

Fetch the catalog metadata for all supported `authorization_details` types.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types` |

#### Sample request

```shell-session
$ curl \
    ${VAULT_ADDR}/v1/sys/oauth-resource-server/authorization-details-types
```

#### Sample response

```json
{
  "data": {
    "api_version": "v1",
    "default_unknown_type_behavior": "deny",
    "types": [
      {
        "type": "vault:path_access",
        "status": "generally-available",
        "schema_version": "1.0.0",
        "title": "Vault Path Access",
        "description": "Constrains a token to specific Vault path/capability combinations.",
        "docs_url": "https://developer.hashicorp.com/vault/docs/auth/jwt/oauth-rar",
        "introduced_in": "2.0.0-ent",
        "schema_path": "/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema"
      }
    ]
  }
}
```

#### Response fields

- `api_version` `(string)` - API version for the type catalog contract (currently "v1").

- `default_unknown_type_behavior` `(string)` - Default behavior for unknown `authorization_details` types (currently "deny").

- `types` `(array)` - Array of type summary objects:
  - `type` `(string)` - Type identifier (for example, "vault:path_access").
  - `status` `(string)` - Lifecycle status. Must be one of:
    - `generally-available`
    - `beta`
    - `experimental`
    - `deprecated`
    - `retired`
  - `schema_version` `(string)` - Semantic version of the type schema (`MAJOR.MINOR.PATCH`).
  - `title` `(string)` - Human-readable type title.
  - `description` `(string)` - Human-friendly summary of how Vault uses the access type.
  - `docs_url` `(string)` - URL to detailed documentation.
  - `introduced_in` `(string)` - Vault version that introduced the type.
  - `deprecated_in` `(string)` - Vault version that deprecated the type. Vault
    omits the `deprecated_in` for non-deprecated types.
  - `schema_path` `(string)` - API path to retrieve the JSON Schema.

### Read authorization details type

Fetch the detailed metadata for a specific `authorization_details` type.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types/:type` |

#### Parameters

- `type` `(string: <required>)` - The `authorization_details` type identifier (for example, "vault:path_access"). Specified in the URL.

#### Sample request

```shell-session
$ curl \
    ${VAULT_ADDR}/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access
```

#### Sample Response

```json
{
  "data": {
    "type": "vault:path_access",
    "status": "generally-available",
    "schema_version": "1.0.0",
    "title": "Vault Path Access",
    "description": "Constrains a token to specific Vault path/capability combinations.",
    "docs_url": "https://developer.hashicorp.com/vault/docs/auth/jwt/oauth-rar",
    "introduced_in": "2.0.0-ent",
    "required_fields": ["type", "path", "capabilities"],
    "optional_fields": [],
    "matching_semantics": {
      "path_match": "evaluated_using_vault_acl_path_matching_semantics",
      "capability_match": "evaluated_using_vault_acl_operation_authorization_semantics"
    },
    "examples": [
      {
        "type": "vault:path_access",
        "path": "kv/data/team-a/secret",
        "capabilities": ["read"]
      }
    ],
    "schema_path": "/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema"
  }
}
```

#### Response Fields

- `type` `(string)` - Type identifier.
- `status` `(string)` - Lifecycle status.
- `schema_version` `(string)` - Semantic version of the type schema.
- `title` `(string)` - Human-readable type title.
- `description` `(string)` - Detailed description.
- `docs_url` `(string)` - URL to documentation.
- `introduced_in` `(string)` - Vault version that introduced the type.
- `deprecated_in` `(string)` - Vault version that deprecated the type. Vault
  omits `deprecated_in` for non-deprecated types.
- `required_fields` `(array)` - List of required field names.
- `optional_fields` `(array)` - List of optional field names.
- `matching_semantics` `(object)` - Description of how Vault evaluates the type.
- `examples` `(array)` - Example `authorization_details` payloads.
- `schema_path` `(string)` - API path to retrieve the JSON Schema.

### Read authorization details type schema

Fetch the machine-readable JSON Schema for a specific `authorization_details` type.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types/:type/schema` |

#### Parameters

- `type` `(string: <required>)` - The authorization_details type identifier. Specified in the URL.

#### Sample Request

```shell-session
$ curl \
    ${VAULT_ADDR}/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema
```

#### Sample Response

```json
{
  "data": {
    "type": "vault:path_access",
    "schema_version": "1.0.0",
    "json_schema_draft": "2020-12",
    "schema": {
      "$schema": "https://json-schema.org/draft/2020-12/schema",
      "type": "object",
      "required": ["type", "path", "capabilities"],
      "properties": {
        "type": {
          "const": "vault:path_access"
        },
        "path": {
          "type": "string",
          "minLength": 1
        },
        "capabilities": {
          "type": "array",
          "minItems": 1,
          "uniqueItems": true,
          "items": {
            "type": "string",
            "enum": [
              "read",
              "list",
              "create",
              "update",
              "delete",
              "patch",
              "sudo",
              "subscribe",
              "recover"
            ]
          }
        }
      },
      "additionalProperties": false
    }
  }
}
```

#### Response Fields

- `type` `(string)` - Type identifier.
- `schema_version` `(string)` - Semantic version of the schema.
- `json_schema_draft` `(string)` - JSON Schema draft version (currently "2020-12").
- `schema` `(object)` - Complete JSON Schema document for validation.

## OAuth protected resource metadata

### Read protected resource metadata

Fetch the OAuth protected resource metadata per RFC 9728 for automated discovery by authorization servers.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/protected-resource-metadata` |
| `GET` | `/.well-known/oauth-protected-resource` |

Both paths return identical responses. The well-known endpoint follows RFC 9728 conventions for automated discovery.

#### Sample request

```shell-session
$ curl \
    ${VAULT_ADDR}/v1/sys/oauth-resource-server/protected-resource-metadata
```

Or using the well-known endpoint:

```shell-session
$ curl \
    ${VAULT_ADDR}/.well-known/oauth-protected-resource
```

#### Sample response

```json
{
  "data": {
    "resource": "https://vault.example.com",
    "authorization_servers": [
      "https://auth.example.com",
      "https://auth2.example.com"
    ],
    "authorization_details_types_supported": ["vault:path_access"],
    "bearer_methods_supported": ["header"],
    "rar_types_metadata_endpoint": "/v1/sys/oauth-resource-server/authorization-details-types"
  }
}
```

#### Response fields

- `resource` `(string)` - The redirect address used by Vault as the resource
  server identifier.

- `authorization_servers` `(array)` - List of trusted authorization server issuer
  IDs from enabled OAuth profiles. Omitted when no profiles exist (per RFC 9728).

- `authorization_details_types_supported` `(array)` - List of supported
  `authorization_details` type identifiers.

- `bearer_methods_supported` `(array)` - Token presentation methods (currently
  only "header").

- `rar_types_metadata_endpoint` `(string)` - API path to the `authorization_details`
  type catalog.

## Error responses

### Profile not found

Returned when reading or deleting a non-existent profile:

```json
{
  "errors": ["profile not found"]
}
```

### Type not found

Returned when reading a non-existent `authorization_details` type:

```json
{
  "errors": ["type not found"]
}
```

### Validation errors

Returned when creating/updating a profile with an invalid configuration:

```json
{
  "errors": [
    "issuer_id is required",
    "jwks_uri is required when use_jwks=true",
    "duplicate issuer_id \"https://auth.example.com\" found in profile \"other-profile\""
  ]
}
```

### Validation warnings

Vault may return non-fatal warnings when creating/updating a profile with inconsistent or non-optimized configuration settings:

```json
{
  "warnings": [
    "JWKS URI uses HTTP instead of HTTPS. This is insecure and should only be used in development.",
    "Profile name exceeds 64 characters. Consider using a shorter name for better readability.",
    "Creating a disabled profile. Enable it with enabled=true when ready."
  ]
}
```

## Authentication requirements

### Authenticated endpoints

The following endpoints require a valid Vault token with appropriate permissions:

- `LIST /sys/config/oauth-resource-server`
- `GET /sys/config/oauth-resource-server/:name`
- `GET /sys/config/oauth-resource-server/id/:config_id`
- `POST /sys/config/oauth-resource-server/:name`
- `DELETE /sys/config/oauth-resource-server/:name`

Required capabilities: `["read", "create", "update", "delete"]` on `sys/config/oauth-resource-server/*`

### Unauthenticated endpoints

The following endpoints are intentionally unauthenticated to support automated discovery:

- `LIST /sys/oauth-resource-server/authorization-details-types`
- `GET /sys/oauth-resource-server/authorization-details-types`
- `GET /sys/oauth-resource-server/authorization-details-types/:type`
- `GET /sys/oauth-resource-server/authorization-details-types/:type/schema`
- `GET /sys/oauth-resource-server/protected-resource-metadata`
- `GET /.well-known/oauth-protected-resource`

The unauthenticated endpoints do not expose sensitive configuration data. Vault
limits exposure to the type metadata and schema information.
