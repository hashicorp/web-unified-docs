# OAuth Resource Server HTTP API

@include 'alerts/enterprise-only.mdx'

The `/sys/oauth-resource-server` endpoints provide OAuth Resource Server configuration management and Rich Authorization Request (RAR) type discovery capabilities. These endpoints support:

- OAuth Resource Server configuration profile management
- Authorization details type catalog discovery (RFC 9396)
- OAuth Protected Resource Metadata publication (RFC 9728)
- JSON Schema retrieval for authorization_details validation

## Configuration Profile Management

### List OAuth Profiles

This endpoint lists all OAuth Resource Server configuration profile names in the current namespace.

| Method | Path |
| :----- | :--- |
| `LIST` | `/sys/config/oauth-resource-server` |

#### Sample Request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    --request LIST \
    https://127.0.0.1:8200/v1/sys/config/oauth-resource-server
```

#### Sample Response

```json
{
  "data": {
    "keys": ["auth0-prod", "okta-dev", "entra-id"]
  }
}
```

### Create/Update OAuth Profile

This endpoint creates or updates an OAuth Resource Server configuration profile.

| Method | Path |
| :----- | :--- |
| `POST`/`PUT` | `/sys/config/oauth-resource-server/:name` |

#### Parameters

- `name` `(string: <required>)` - The name of the OAuth Resource Server configuration profile. Specified in the URL.

- `issuer_id` `(string: <required>)` - The issuer identifier (iss claim) to validate against. Must be a valid URL. Required for create operations.

- `use_jwks` `(boolean: true)` - If true, use JWKS URI for public key validation. If false, use static public keys. Default is true.

- `jwks_uri` `(string: "")` - The JWKS URI to fetch public keys from. Required when `use_jwks=true`. Must be a valid HTTPS URL (HTTP allowed for development only).

- `jwks_ca_pem` `(string: "")` - Optional PEM-encoded CA certificate for JWKS URI TLS validation. Used when the JWKS endpoint uses a custom CA.

- `public_keys` `(array: [])` - List of static public keys. Required when `use_jwks=false`. Each entry must contain:
  - `key_id` `(string: <required>)` - Key identifier (kid)
  - `pem` `(string: <required>)` - PEM-encoded public key or certificate

- `audiences` `(array: [])` - List of allowed audience values (aud claim). If specified, at least one audience must match.

- `no_default_policy` `(boolean: false)` - If true, JWT-authenticated tokens omit the default policy unless applied elsewhere.

- `optional_authorization_details` `(boolean: false)` - If true, the authorization_details claim is optional for OAuth 2.0 JWTs using this profile. By default (false), authorization_details is mandatory when an OAuth profile exists.

- `user_claim` `(string: "sub")` - The JWT claim to use as the Vault entity identifier. Default is "sub".

- `supported_algorithms` `(array: [])` - List of supported signing algorithms (for example, RS256, ES256, PS256). If empty, all algorithms supported by the keys are allowed.

- `jwt_type` `(string: "access_token")` - The JWT type to validate. Must be "access_token" or "transaction_token". Default is "access_token".

- `clock_skew_leeway` `(integer: 0)` - Clock skew leeway in seconds for time-based claim validation (exp, nbf, iat). Default is 0.

- `enabled` `(boolean: true)` - Whether this profile is enabled for JWT validation. Disabled profiles are ignored. Default is true.

#### Sample Payload (JWKS)

```json
{
  "issuer_id": "https://auth.example.com",
  "audiences": ["vault-api"],
  "use_jwks": true,
  "jwks_uri": "https://auth.example.com/.well-known/jwks.json",
  "user_claim": "sub",
  "jwt_type": "access_token",
  "supported_algorithms": ["RS256", "ES256"],
  "clock_skew_leeway": 60,
  "enabled": true
}
```

#### Sample Payload (Static Keys)

```json
{
  "issuer_id": "https://auth.example.com",
  "audiences": ["vault-api"],
  "use_jwks": false,
  "public_keys": [
    {
      "key_id": "key-1",
      "pem": "-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...\n-----END PUBLIC KEY-----"
    }
  ],
  "user_claim": "sub",
  "jwt_type": "access_token"
}
```

#### Sample Request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    --request POST \
    --data @payload.json \
    https://127.0.0.1:8200/v1/sys/config/oauth-resource-server/my-idp
```

#### Sample Response

```json
{
  "warnings": [
    "JWKS URI uses HTTP instead of HTTPS. This is insecure and should only be used in development."
  ]
}
```

### Read OAuth Profile

This endpoint reads an OAuth Resource Server configuration profile.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/config/oauth-resource-server/:name` |

#### Parameters

- `name` `(string: <required>)` - The name of the OAuth Resource Server configuration profile. Specified in the URL.

#### Sample Request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    https://127.0.0.1:8200/v1/sys/config/oauth-resource-server/my-idp
```

#### Sample Response

```json
{
  "data": {
    "config_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "profile_name": "my-idp",
    "issuer_id": "https://auth.example.com",
    "use_jwks": true,
    "jwks_uri": "https://auth.example.com/.well-known/jwks.json",
    "audiences": ["vault-api"],
    "no_default_policy": false,
    "optional_authorization_details": false,
    "user_claim": "sub",
    "supported_algorithms": ["RS256", "ES256"],
    "jwt_type": "access_token",
    "clock_skew_leeway": 60,
    "enabled": true
  }
}
```

Same as Read OAuth Profile response.

## Authorization Details Type Discovery

The following endpoints support OAuth 2.0 Rich Authorization Request (RAR) type discovery per RFC 9396 and RFC 9728. These endpoints are **unauthenticated** to support automated discovery by Authorization Servers and clients.

### List Authorization Details Types

This endpoint lists all supported authorization_details type identifiers.

| Method | Path |
| :----- | :--- |
| `LIST` | `/sys/oauth-resource-server/authorization-details-types` |

#### Sample Request

```shell-session
$ curl \
    --request LIST \
    https://127.0.0.1:8200/v1/sys/oauth-resource-server/authorization-details-types
```

#### Sample Response

```json
{
  "data": {
    "keys": ["vault:path_access"]
  }
}
```

### Read Authorization Details Type Catalog

This endpoint returns catalog metadata for all supported authorization_details types.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types` |

#### Sample Request

```shell-session
$ curl \
    https://127.0.0.1:8200/v1/sys/oauth-resource-server/authorization-details-types
```

#### Sample Response

```json
{
  "data": {
    "api_version": "v1",
    "default_unknown_type_behavior": "deny",
    "types": [
      {
        "type": "vault:path_access",
        "status": "generally-available",
        "schema_version": "1.0.0",
        "title": "Vault Path Access",
        "description": "Constrains a token to specific Vault path/capability combinations.",
        "docs_url": "https://developer.hashicorp.com/vault/docs/auth/jwt/oauth-rar",
        "introduced_in": "2.0.0-ent",
        "schema_path": "/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema"
      }
    ]
  }
}
```

#### Response Fields

- `api_version` `(string)` - API version for the type catalog contract (currently "v1")

- `default_unknown_type_behavior` `(string)` - Default behavior for unknown authorization_details types (currently "deny")

- `types` `(array)` - Array of type summary objects:
  - `type` `(string)` - Type identifier (for example, "vault:path_access")
  - `status` `(string)` - Lifecycle status (generally-available, beta, experimental, deprecated, retired)
  - `schema_version` `(string)` - Semantic version of the type schema (MAJOR.MINOR.PATCH)
  - `title` `(string)` - Human-readable type title
  - `description` `(string)` - Brief description of the type's purpose
  - `docs_url` `(string)` - URL to detailed documentation
  - `introduced_in` `(string)` - Vault version that introduced this type
  - `deprecated_in` `(string)` - Vault version that deprecated this type (only present if deprecated)
  - `schema_path` `(string)` - API path to retrieve the JSON Schema

### Read Authorization Details Type

This endpoint returns detailed metadata for a specific authorization_details type.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types/:type` |

#### Parameters

- `type` `(string: <required>)` - The authorization_details type identifier (for example, "vault:path_access"). Specified in the URL.

#### Sample Request

```shell-session
$ curl \
    https://127.0.0.1:8200/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access
```

#### Sample Response

```json
{
  "data": {
    "type": "vault:path_access",
    "status": "generally-available",
    "schema_version": "1.0.0",
    "title": "Vault Path Access",
    "description": "Constrains a token to specific Vault path/capability combinations.",
    "docs_url": "https://developer.hashicorp.com/vault/docs/auth/jwt/oauth-rar",
    "introduced_in": "2.0.0-ent",
    "required_fields": ["type", "path", "capabilities"],
    "optional_fields": [],
    "matching_semantics": {
      "path_match": "evaluated_using_vault_acl_path_matching_semantics",
      "capability_match": "evaluated_using_vault_acl_operation_authorization_semantics"
    },
    "examples": [
      {
        "type": "vault:path_access",
        "path": "kv/data/team-a/secret",
        "capabilities": ["read"]
      }
    ],
    "schema_path": "/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema"
  }
}
```

#### Response Fields

- `type` `(string)` - Type identifier
- `status` `(string)` - Lifecycle status
- `schema_version` `(string)` - Semantic version of the type schema
- `title` `(string)` - Human-readable type title
- `description` `(string)` - Detailed description
- `docs_url` `(string)` - URL to documentation
- `introduced_in` `(string)` - Vault version that introduced this type
- `deprecated_in` `(string)` - Vault version that deprecated this type (only present if deprecated)
- `required_fields` `(array)` - List of required field names
- `optional_fields` `(array)` - List of optional field names
- `matching_semantics` `(object)` - Description of how Vault evaluates this type
- `examples` `(array)` - Example authorization_details payloads
- `schema_path` `(string)` - API path to retrieve the JSON Schema

### Read Authorization Details Type Schema

This endpoint returns the machine-readable JSON Schema for a specific authorization_details type.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/authorization-details-types/:type/schema` |

#### Parameters

- `type` `(string: <required>)` - The authorization_details type identifier. Specified in the URL.

#### Sample Request

```shell-session
$ curl \
    https://127.0.0.1:8200/v1/sys/oauth-resource-server/authorization-details-types/vault:path_access/schema
```

#### Sample Response

```json
{
  "data": {
    "type": "vault:path_access",
    "schema_version": "1.0.0",
    "json_schema_draft": "2020-12",
    "schema": {
      "$schema": "https://json-schema.org/draft/2020-12/schema",
      "type": "object",
      "required": ["type", "path", "capabilities"],
      "properties": {
        "type": {
          "const": "vault:path_access"
        },
        "path": {
          "type": "string",
          "minLength": 1
        },
        "capabilities": {
          "type": "array",
          "minItems": 1,
          "uniqueItems": true,
          "items": {
            "type": "string",
            "enum": [
              "read",
              "list",
              "create",
              "update",
              "delete",
              "patch",
              "sudo",
              "subscribe",
              "recover"
            ]
          }
        }
      },
      "additionalProperties": false

  }

```

#### Response Fields

- `type` `(string)` - Type identifier
- `schema_version` `(string)` - Semantic version of the schema
- `json_schema_draft` `(string)` - JSON Schema draft version (currently "2020-12")
- `schema` `(object)` - Complete JSON Schema document for validation

## OAuth Protected Resource Metadata

### Read Protected Resource Metadata

This endpoint returns OAuth Protected Resource Metadata per RFC 9728 for automated discovery by Authorization Servers.

| Method | Path |
| :----- | :--- |
| `GET` | `/sys/oauth-resource-server/protected-resource-metadata` |
| `GET` | `/.well-known/oauth-protected-resource` |

Both paths return identical responses. The well-known endpoint follows RFC 9728 conventions for automated discovery.

#### Sample Request

```shell-session
$ curl \
    https://127.0.0.1:8200/v1/sys/oauth-resource-server/protected-resource-metadata
```

Or using the well-known endpoint:

```shell-session
$ curl \
    https://127.0.0.1:8200/.well-known/oauth-protected-resource
```

#### Sample Response

```json
{
  "data": {
    "resource": "https://vault.example.com",
    "authorization_servers": [
      "https://auth.example.com",
      "https://auth2.example.com"
    ],
    "authorization_details_types_supported": ["vault:path_access"],
    "bearer_methods_supported": ["header"],
    "rar_types_metadata_endpoint": "/v1/sys/oauth-resource-server/authorization-details-types"
  }
}
```

#### Response Fields

- `resource` `(string)` - Resource server identifier (Vault's redirect address)

- `authorization_servers` `(array)` - List of trusted Authorization Server issuer IDs from enabled OAuth profiles. Omitted when no profiles exist (per RFC 9728).

- `authorization_details_types_supported` `(array)` - List of supported authorization_details type identifiers

- `bearer_methods_supported` `(array)` - Token presentation methods (currently only "header")

- `rar_types_metadata_endpoint` `(string)` - API path to the authorization_details type catalog

## Error Responses

### Feature Not Enabled

When the `oauth-resource-server` feature flag is not enabled, all endpoints return 404:

```json
{
  "errors": ["unsupported path"]
}
```

### Profile Not Found

When reading or deleting a non-existent profile:

```json
{
  "errors": ["profile not found"]
}
```

### Type Not Found

When reading a non-existent authorization_details type:

```json
{
  "errors": ["type not found"]
}
```

### Validation Errors

When creating/updating a profile with invalid configuration:

```json
{
  "errors": [
    "issuer_id is required",
    "jwks_uri is required when use_jwks=true",
    "duplicate issuer_id \"https://auth.example.com\" found in profile \"other-profile\""
  ]
}
```

### Validation Warnings

Non-fatal warnings may be returned in the response:

```json
{
  "warnings": [
    "JWKS URI uses HTTP instead of HTTPS. This is insecure and should only be used in development.",
    "Profile name exceeds 64 characters. Consider using a shorter name for better readability.",
    "Creating a disabled profile. Enable it with enabled=true when ready."
  ]
}
```

## Feature Flag Requirement

All OAuth Resource Server endpoints require the `oauth-resource-server` feature flag to be enabled:

```shell-session
$ vault write sys/activation-flags/oauth-resource-server enabled=true
```

When the feature flag is disabled, all endpoints return HTTP 404 (unsupported path).

## Authentication Requirements

### Authenticated Endpoints

The following endpoints require a valid Vault token with appropriate permissions:

- `LIST /sys/config/oauth-resource-server`
- `GET /sys/config/oauth-resource-server/:name`
- `GET /sys/config/oauth-resource-server/id/:config_id`
- `POST /sys/config/oauth-resource-server/:name`
- `DELETE /sys/config/oauth-resource-server/:name`

Required capabilities: `["read", "create", "update", "delete"]` on `sys/config/oauth-resource-server/*`

### Unauthenticated Endpoints

The following endpoints are intentionally unauthenticated to support automated discovery:

- `LIST /sys/oauth-resource-server/authorization-details-types`
- `GET /sys/oauth-resource-server/authorization-details-types`
- `GET /sys/oauth-resource-server/authorization-details-types/:type`
- `GET /sys/oauth-resource-server/authorization-details-types/:type/schema`
- `GET /sys/oauth-resource-server/protected-resource-metadata`
- `GET /.well-known/oauth-protected-resource`

These endpoints expose only type metadata and schema information, not sensitive configuration data.
