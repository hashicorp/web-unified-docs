# Vault Secrets Operator release notes

Review the new features and breaking changes in each release of the Vault
Secrets Operator before you upgrade.

## Vault Secrets Operator 2.0.0

**Released**: 2026-11-12

### Breaking changes

- **Removed the `kube-rbac-proxy` sidecar**: The Vault Secrets Operator
  Deployment no longer includes the `kube-rbac-proxy` container
  (`quay.io/brancz/kube-rbac-proxy`, or `ose-kube-rbac-proxy` on OpenShift), so
  the operator no longer requires a second container image. The operator now
  serves the `/metrics` endpoint over HTTPS on port `8443` and runs the same
  `TokenReview` and `SubjectAccessReview` authentication and authorization
  checks itself. The metrics Service, its port, the ServiceMonitor, and the
  metrics RBAC are unchanged, so existing scrape configurations continue to
  work. Before you upgrade, review the following changes:

  - **Prometheus Operator**: Scraped metrics now carry the label
    `container="manager"` instead of `container="kube-rbac-proxy"`. Update any
    dashboards, alerts, or recording rules that filter on the old label value.
  - **Invalid bearer tokens**: Requests to `/metrics` with an invalid bearer
    token now return HTTP `500` instead of `401`, and the operator logs the
    failure at the error level.
  - **Helm**: The chart no longer supports the `controller.kubeRbacProxy.*`
    values and ignores them if they are set. Remove them from your values
    files, and use
    [`controller.manager.resources`](/vault/docs/deploy/kubernetes/vso/helm#v-controller-manager-resources)
    to tune the operator's resources.
  - **Kustomize**: Remove any custom patches that target the `kube-rbac-proxy`
    container. Otherwise, the patches add a broken container back to the
    Deployment.

  Refer to [Vault Secrets Operator telemetry](/vault/docs/deploy/kubernetes/vso/telemetry),
  the [`metricsService` Helm values](/vault/docs/deploy/kubernetes/vso/helm#h-metricsservice),
  and [Install and upgrade the Vault Secrets Operator](/vault/docs/deploy/kubernetes/vso/installation)
  for more information.

### New features

- **[Issue certificates with cert-manager](/vault/docs/deploy/kubernetes/vso/cert-manager)** <EnterpriseAlert inline="true" />:
  The Vault Secrets Operator can act as a cert-manager external issuer with the
  new `VaultIssuer` and `VaultClusterIssuer` resources. Applications request
  certificates with standard cert-manager `Certificate` resources, and the
  operator signs each request with the Vault PKI secrets engine, using the same
  `VaultConnection` and `VaultAuth` resources that it uses to sync secrets. The
  issuers require Vault Enterprise.

  To get started, refer to
  [Set up the cert-manager issuer](/vault/docs/deploy/kubernetes/vso/cert-manager/setup).
  To move existing certificates from the Vault issuer built into cert-manager,
  refer to
  [Migrate from the cert-manager Vault issuer](/vault/docs/deploy/kubernetes/vso/cert-manager/migrate).
  For the full resource specification, refer to
  [`VaultIssuer`](/vault/docs/deploy/kubernetes/vso/api-reference#vaultissuer)
  and
  [`VaultClusterIssuer`](/vault/docs/deploy/kubernetes/vso/api-reference#vaultclusterissuer)
  in the API reference.

### Bug fixes

- **`VaultStaticSecret` rollout restarts**: The operator now restarts
  `rolloutRestartTargets` only when the secret data changes, not when a `.spec`
  change leaves the data unchanged.
