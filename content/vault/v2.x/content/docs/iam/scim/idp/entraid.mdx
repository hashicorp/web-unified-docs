# Configure Microsoft Entra ID for SCIM with Vault

@include 'alerts/enterprise-only.mdx'

Microsoft Entra ID uses two separate applications for this workflow. An OpenID Connect (OIDC) application authenticates your users to Vault, and a SCIM application provisions those users into Vault as entities.

Follow the instructions to configure an example Entra ID application and user that
act as a SCIM client to a Vault SCIM server.

Each application depends on values from the other product, so the workflow alternates between the Entra ID Admin Console and Vault:

1. Create the Entra ID OIDC application and an user.
1. Configure Vault with the OIDC application credentials, then create the SCIM client and its token.
1. Create the Entra ID SCIM application and authenticate it with that token.

## Before you start

- **Get an Microsoft Azure subscription**.  Use an existing subscription or [Sign up for a free account](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account?icid=azurefreeaccount)

- **[Create a Microsoft Entra tenant](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-create-new-tenant)**. Note down the **Tenant ID**.

- **Run a Vault Enterprise cluster that Entra ID can reach**. Entra ID sends SCIM requests from its own network, so the Vault API address must accept those requests.

- **[Set up a Vault SCIM server](/vault/docs/iam/scim/setup)**. Take note of the URL of your Vault instance.  The SCIM endpoint will be `http://YOUR_VAULT_ADDR/v1/admin/identity/scim/v2/Users`.

- **Check your permissions**. On Azure, you must be able to:
   - create and edit Microsoft Entra ID applications, groups and users
   - create policies, entities, and SCIM clients in Vault

## Create the Entra ID OIDC SSO application

Configure the OIDC SSO application with the following settings and replace the example values with your own values.

This is a generic application, registered under **App registrations** -> **New registration**.

After creating the application, update the redirect URI's under App registrations -> Your app name -> Authentication.  

After finished there should be three Web redirect URIs.

| Configuration setting | Value                                                |
|-----------------------|---------------------------|---------------------------|
| Web Redirect URI | https://vault-addr:8200/v1/admin/auth/oidc/callback  |
| Web Redirect URI | https://vault-addr:8200/ui/vault/auth/oidc/oidc/callback |
| Web Redirect URI | http://localhost:8250/oidc/callback |

Create a new client secret. Copy the **Value** and **Secret ID**.  This is the last chance to copy the **Value**.  Be sure to save this information.

From the overview, copy **Application (client) ID** and **Directory (tenant) ID**.

For the **token configuration** add an optional claim.  
- Add an optional claim
- Token Type: email

After adding, if prompted anbout enabling openID connect click add.

API permission **+ Add a permission**. Microsoft Graph, Delegated permisions, add openid, email, profile.  Add permissions -> Grant admin consent -> Yes

Provisioning should not be enabled.

## Get values and export environment variables

You must capture some values from Entra ID, and export them as environment variables to use when you set up a Vault SCIM server.

- Within the Azure admin portal, [find your Microsoft Entra tenant](https://learn.microsoft.com/en-us/azure/azure-portal/get-subscription-tenant-id#find-your-microsoft-entra-tenant).
- The **Client ID** and **Value** from [Create the Entra ID OIDC SSO application](#create-the-entra-id-oidc-sso-application)

Use the values you captured in the shell session where you plan to set up Vault for SCIM.

```shell-session
$ export ENTRA_ID_DOMAIN="nnnn-nnnn-nnnn-nnnn-nnnnnnnnnnnn" \
    ENTRA_ID_CLIENT_ID="<client-id-value>" \
    ENTRA_ID_CLIENT_SECRET="<client-secret-value>"
```

## Configure Vault for Entra ID

Vault needs the OIDC application credentials before your users can log in, and the Entra ID SCIM application needs a Vault token before it can provision anyone.

Complete both tasks in [Set up a Vault SCIM server](/vault/docs/iam/scim/setup) before you continue.

Confirm that Vault enables the OIDC authentication method. Some deployments, including HCP Vault Dedicated, do not enable the method by default.

List the enabled authentication methods.

```shell-session
$ vault auth list
```

Enable the OIDC method when the output does not include `oidc/`.

```shell-session
$ vault auth enable oidc
```

When you finish the Vault configuration, you have:

- an OIDC role that your users authenticate with, for example
  `vault-role-entra-default`
- a SCIM client bound to an access grant principal
- a SCIM token that begins with `scm.`

<Note title="Match the discovery URL to your Tenant">

Set `oidc_discovery_url` to the issuer of the authorization server that serves your groups claim.  For Microsoft Entra ID the default is `https://login.microsoftonline.com/YOUR_TENANT_ID/v2.0`.  See [OIDC endpoint overview](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols-oidc#oidc-endpoint-overview) for details.

</Note>

## Log into Vault through Entra ID

Users authenticate to Vault through the browser, and the Okta identity becomes a Vault entity. Log in now to confirm that the OIDC configuration works before you configure provisioning.

The SCIM client authenticates with its own token and its own entity, so the entity from this login does not act as the SCIM client.

1. Log in to Vault UI.  open your browser and go to `https://vault-addr:8200/ui`.

1. Choose OIDC in the dropdown.

1. Log in as the user created earlier.

1. Verify that the Vault entity matches the Entra ID user name.

   ```shell-session
   vault read identity/entity/name/<entity-name> | grep -E "scim_client_id|name|aliases" 
   ```
