# Mint an SVID with Vault and authenticate with Grafana

@include 'alerts/enterprise-only.mdx'

You can use a JWT-SVID minted by Vault to authenticate with services that
support SPIFFE. 

If you are not familiar with SPIFFE, refer to the [SPIFFE
overview](/vault/docs/secrets/spiffe) to learn more about how the SPIFFE secrets
engine works in Vault.

This document is meant to be followed as written. Following these steps on
production hosts will change their configuration. Refer to the [setup
guide](/vault/docs/secrets/spiffe/spiffe) for general configuration instructions.

Vault and the relying party used in this doc both run as containers on
one Docker network for simplicity.

## Requirements 

- An active Vault Enterprise license.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) installed.

## Set up Vault

This section walks through the minimum configuration needed to get a workload
authenticating with a Vault minted SVID. It is not a SPIFFE production or hardening guide.

1. Create a Docker network to run Vault and Grafana.

   ```shell-session
   $ docker network create spiffe-demo
   ```
1. Export your Vault Enterprise license as an environment variable.

   ```shell-session
   $ export VAULT_LICENSE=C10WMSH0W...snip...S3ASM3STR33T
   ```

1. Start Vault.

   ```shell-session
   $ docker run -d --name vault --network spiffe-demo -p 8200:8200 \
       -e 'VAULT_DEV_ROOT_TOKEN_ID=root' \
       -e 'VAULT_LICENSE=<your Enterprise license>' \
       hashicorp/vault-enterprise:latest \
       server -dev
   ```

   <Warning title="Root tokens">
   
   The dev mode server starts with an initial root token value set.
   
   Root token use should be extremely guarded in production environments because
   it provides full access to the Vault server.
   
   You can supply the root token value to start Vault in dev mode for
   convenience and to keep the steps here focused on the learning goals of
   this tutorial.
   
   </Warning>

1. Export environment variables to access Vault.

   ```shell-session
   $ export VAULT_ADDR="http://127.0.0.1:8200" VAULT_TOKEN="root"
   ```

1. Enable the engine.

   ```shell-session
   $ vault secrets enable spiffe
   Success! Enabled the spiffe secrets engine at: spiffe/
   ```

1. Configure the trust domain.

   ```shell-session
   $ vault write spiffe/config trust_domain=example.org
   ```

1. Create a role.

   ```shell-session
   $ vault write spiffe/role/workload \
       template='{"sub": "/payments-api"}' \
       ttl=5m
   ```

   `sub` is given as a path here — Vault expands it to
   `spiffe://example.org/payments-api` when it mints a token.

1. Mint a JWT-SVID.

    ```shell-session
    $ JWT_SVID=$(vault write -format=json \
       spiffe/role/workload/mintjwt \
       audience=example-relying-party) \
       | jq -r '.data.token' \
       && echo $JWT_SVID
    ```

   <Warning title="Test">
 
   CONFIRM: the field holding the JWT in this response. The API docs don't
   publish a sample response for mintjwt (every other endpoint on this page
   does) - check the raw output above and swap the jq path below to match.
 
   </Warning>

   ```shell-session
   $ jq -r '.data.token' svid.json > svid.jwt
   ```

1. Review the JWT claims.
   
   ```shell-session
   $ echo $JWT_SVID | base64 -d 2>/dev/null | jq .
   ```
   JWTs are three base64url segments separated by `.`.
   
   You should see `sub` set to `spiffe://example.org/payments-api`, plus
   `iss`, `aud`, `iat`, `exp`, and `vault.entity.id`.

1. Fetch the engine's published keys:

   ```shell-session
   $ curl -s $VAULT_ADDR/v1/spiffe/.well-known/openid-configuration | jq . && \
   $ curl -s $VAULT_ADDR/v1/spiffe/.well-known/keys | jq .
   ```

   Any OIDC-compatible JWT library can take the JWKS from `.well-known/keys`
   and verify `svid.jwt` directly — that's the same endpoint a real relying
   party, or another Vault's SPIFFE auth method trust bundle config, would use.

## Log in with the JWT-SVID

To see the JWT-SVID accepted by something other than Vault, run
[Grafana](https://grafana.com/oss/grafana/) with its built-in JWT auth
pointed at the engine's JWKS endpoint. Grafana's JWT auth needs only a JWKS
URL.

<Note>

This is a simple example of running Grafana, not suitable for a production
deployment.

</Note>

1. Start Grafana.

   ```shell-session
   $ docker run -d --name grafana --network spiffe-demo -p 3000:3000 \
       -e "GF_AUTH_JWT_ENABLED=true" \
       -e "GF_AUTH_JWT_HEADER_NAME=X-JWT-Assertion" \
       -e "GF_AUTH_JWT_JWK_SET_URL=http://vault:8200/v1/spiffe/.well-known/keys" \
       -e "GF_AUTH_JWT_USERNAME_CLAIM=sub" \
       -e "GF_AUTH_JWT_AUTO_SIGN_UP=true" \
       grafana/grafana-oss:latest
   ```

1. Log into Grafana with the SVID minted by Vault.

   ```shell-session
   $ curl -H "X-JWT-Assertion: $(cat svid.jwt)" http://localhost:3000/api/user
   ```

   A successful response returns the logged-in user, with `login` set to the
   SPIFFE ID from the `sub` claim — Grafana accepting the JWT-SVID as a valid
   credential.
