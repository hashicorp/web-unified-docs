## Known Issues

## Breaking Changes

1. Terraform Enterprise now disables public self-registration by default. This change does not apply to instances configured with SAML authentication. Previously, public self-registration was enabled by default. Instances that relied on default open registration will have unauthenticated sign-ups blocked after upgrade until a site administrator explicitly enables the setting. To preserve open-registration behavior, set `enable-public-registration` to `true` using the [Admin Settings API](/terraform/enterprise/api-docs/admin/settings#update-general-settings), or enable **Enable public registration** in [**Admin** > **Settings**](/terraform/enterprise/application-administration/general#public-registration).

1. **Agent-based VCS ingress** - Terraform Enterprise now packages version control operations in an agent job instead of the standalone `slug-ingress` service. Your agents must be able to reach your VCS servers. On Kubernetes, allow egress to your VCS servers from the agents namespace. Refer to [Configure network access](/terraform/enterprise/deploy/configuration/network) for more information. Ingress jobs run alongside your other agent workloads and do not count against an organization's run concurrency. They use the same image, CPU, and memory settings as run agents, and create additional agent containers on Docker and Podman, agent jobs on Nomad, and agent pods in your agents namespace on Kubernetes. Refer to [Increase run capacity on Kubernetes](/terraform/enterprise/deploy/kubernetes/scale/run-capacity#account-for-agent-based-vcs-ingress) to size the agents namespace. To keep the Terraform Enterprise 2.0 behavior while you update your network rules, set [`TFE_VCS_INGRESS_SLUG_INGRESS_FALLBACK`](/terraform/enterprise/deploy/reference/configuration#tfe_vcs_ingress_slug_ingress_fallback) to `true` and restart Terraform Enterprise.

## Deprecations

1. In a future release, Terraform Enterprise will be transitioning to Red Hat Universal Base Image (UBI) as its base operating system. If you have built a custom Terraform Enterprise image on top of the current base image, you will need to rebuild your image and update any OS-specific customizations for compatibility. Note that IBM does not recommend building custom Terraform Enterprise images — running the official, unmodified image is the supported deployment path. If you have specific requirements that led you to create a custom image, contact your IBM account representative.

1. The `idp-cert` and `old-idp-cert` attributes in the `admin/saml-settings` endpoint, and the `admin/saml-settings/actions/revoke-old-certificate` action, are deprecated and will be removed in a future release. This is part of the transition to multiple SAML IdP certificates. Use the [SAML IdP Certificates API](/terraform/enterprise/api-docs/admin/saml-idp-certificates) instead.

1. [Built-in Fluent Bit log forwarding](/terraform/enterprise/deploy/manage/monitor/logs#native-log-forwarding) is deprecated and will no longer be supported starting in October 2027. We recommend configuring [external log forwarding](/terraform/enterprise/deploy/manage/monitor/logs#external-log-forwarding) using your platform's native container logging drivers or host-level observability agents.

1. [VCS ingress fallback to the `slug-ingress` service](/terraform/enterprise/deploy/reference/configuration#tfe_vcs_ingress_slug_ingress_fallback) is deprecated and will no longer be supported starting in October 2027. We recommend [allowing your agents to reach your VCS servers](/terraform/enterprise/deploy/configuration/network) so that Terraform Enterprise can perform VCS ingress in agent jobs.

## Highlights

1. **Terraform Policy** - Terraform Enterprise now supports Terraform Policy, a declarative, HCL-based policy-as-code framework integrated directly with Terraform and provider schemas that enables you to author, test, and enforce governance policies across workspaces and Stacks natively within your Terraform workflow.

1. **Tag-based policy set scoping** - Terraform Enterprise now supports scoping a policy set to workspaces with matching tags, in addition to scoping by project or workspace, increasing the flexibility of targeting. Policy sets scoped to tags use a tag match logic of **And**, which requires all selected tags to be present on a workspace, or **Or**, which requires at least one selected tag to be present on a workspace. Refer to [Manage policy sets](/terraform/enterprise/workspaces/policy-enforcement/manage-policy-sets/configure) for more information.

1. **Project-level run tasks** - Terraform Enterprise now supports project-level run tasks, enabling organizations to apply security, compliance, and operational guardrails consistently across groups of workspaces while reducing manual overhead. Refer to [Terraform run tasks](/terraform/enterprise/workspaces/settings/run-tasks#scope-a-run-task-to-an-organization-or-project) for more information.

1. **Migrate workspaces to stacks** - You can now use the [`terraform stacks migrate`](/terraform/cloud-docs/stacks/migrate) command group to migrate existing workspaces into Terraform Stacks. The migration workflow automatically scaffolds Stack configuration, translates workspace state files into deployment-level Stack state, and imports resources into Stacks.

1. **No Code Search** - Terraform Enterprise let you search your existing infrastructure for unmanaged resources and import them into your workspace from the user interface without writing HCL, making it easier to bring existing infrastructure under Terraform management.

1. **Registry artifact tagging** - You can now tag private registry modules, providers, and stack component configs with project tags, and tag their individual versions with environment tags resulting in easier organization and discovery of the appropriate registry artifacts.

1. **Restore deleted workspaces and stacks** -  Site administrators and organization owners can now restore recently deleted workspaces and stacks from a recoverable trash state, reducing recovery effort and risk from accidental deletion.

1. **Global banner and link customization** - Site administrators can now configure custom site-wide notification banners and override default platform help links. You can publish informational, warning, or critical banners with optional scheduling windows and audience targeting, as well as replace built-in documentation, tutorial, and support links with internal URLs.

1. **Data retention policies by artifact type** - Terraform Enterprise now lets you configure data retention policies separately for configuration versions, state versions, and run data and logs, including plans, applies, and assessments. You can also retain a specific number of the most recent versions for each resource and artifact type.

1. **Node drain status** - Terraform Enterprise introduces a Node Drain Status API that lets you check whether a node is safe to terminate before removing it from a deployment. Use these endpoints to avoid interrupting active Terraform runs during node maintenance or scaling operations.

1. **Modify node configuration without restart** - You can now modify specific configuration values on a running Terraform Enterprise node without restarting it. Refer to [Modify node configuration](/terraform/enterprise/application-administration/config-reload) for more information.

## Features

1. **Integration with IBM Cloudability** - Terraform Enterprise now supports the Cloudability native task integration (public beta). The Cloudability native task enables cost estimation, FinOps policy evaluation, and optimization recommendations as part of your infrastructure automation workflow, without requiring users to leave Terraform. This integration requires tfc-agent version 1.31.1 or later, and your instance must be able to reach Cloudability endpoints for your region.

1. **Multiple SAML IdP certificates** - Terraform Enterprise previously trusted exactly one active SAML IdP certificate, plus one temporary certificate during a rotation window. Terraform Enterprise now stores IdP certificates as a collection and verifies each SAML response against every trusted certificate, so an identity provider that signs with different certificates per region no longer breaks logins during a failover. Refer to [Manage IdP certificates](/terraform/enterprise/saml/configuration#manage-idp-certificates) for more information.

1. **Admin console access modes** - Terraform Enterprise introduces the `TFE_ADMIN_CONSOLE_ACCESS_MODE` environment variable, which provides flexible options for accessing the admin console via a dedicated port, or via standard HTTPS path. Refer to [Access the admin console](/terraform/enterprise/deploy/manage/access-admin-console) for additional information.

1. **Pod-level workload identity** - Terraform Enterprise deployments on Kubernetes now support pod-level workload identity federation for Azure, AWS, and GCP, allowing TFE pods to authenticate to external PostgreSQL, Redis, and storage services without passwords or node-level managed identities, improving security isolation in multi-tenant cluster environments.

1. **Redis 8.0 and Valkey 9.0** - Terraform Enterprise now supports Redis 8.0 and Valkey 9.0 for the required external cache. Valkey is a drop-in replacement for Redis and uses the same connection settings.

1. **Support for IBM Cloud** - You can now deploy Terraform Enterprise to IBM Cloud giving you additional flexibility when hosting Terraform Enterprise in your cloud environment. You can also use the [Terraform Enterprise on IBM Cloud deployable architecture](https://cloud.ibm.com/catalog/7a4d68b4-cf8b-40cd-a3d1-f49aff526eb3/architecture/deploy-arch-ibm-terraform-enterprise-42170cf3-6337-453e-8d2d-ffabd48c4914-global) to automate deployment with supporting IBM Cloud services.

## Improvements

1. **Token expiration notification** - Terraform Enterprise sends notification emails at 30 days and seven days before a user, team, audit, or organization token expires. The expiration window is intended to give you sufficient time to rotate or renew tokens before they expire.

1. The Team Tokens page now supports improved filtering by token expiration status and bulk deletion, making it easier to find and manage multiple tokens.

1. **Revoke user tokens** - Site administrators can now view and revoke API tokens for any user in the organization directly from the admin UI or via the API, improving token governance and security compliance in environments where non-expiring user tokens pose a policy risk.

1. You can now use dynamic provider credentials with Tencent Cloud by configuring Terraform Enterprise as an OIDC relying party, eliminating the need for static credentials in workspace configurations.

1. **Site Auditor role through identity provider** - Terraform Enterprise now provisions the read-only Site Auditor role automatically through your identity provider. Configure a SAML attribute or role, or map a SCIM group, to grant and revoke cross-organization Site Auditor access without manual admin action. When SCIM is enabled, SAML auditor provisioning is skipped. The role is Terraform Enterprise only and cannot be granted to service accounts. Refer to the SAML and SCIM configuration guides for details.

1. The Quick Filter buttons on the Workspaces page now adapt and display properly across all screen sizes. Previously, a layout bug affected their responsive behavior on certain screen resolutions.

1. You can now view full project names when filtering workspaces. The workspace filter has been redesigned into an inline bar that wraps long names onto multiple lines, preventing truncation.

1. You can now use a dedicated Actions page to discover, review, and invoke Day 2 operational workflows and remediation actions directly from the user interface. You can also monitor active and historical action runs to audit ad hoc operations and troubleshoot operational issues across your environment.

1. **Disable gravatar.com** - Site administrators can now disable outbound requests to gravatar.com by configuring Terraform Enterprise to display a default avatar icon instead, improving privacy and compatibility with restricted network environments.

1. Redis mTLS connections now support password authentication. Both can be enabled at the same time - certificate-based mutual TLS and Redis ACL credentials.

1. The Azure object storage configuration now supports block size and concurrency parameters, which brings it closer to parity with the AWS object storage configuration.
