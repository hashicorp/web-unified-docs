- **Release Branch:** release/2.1.0

## Known Issues

## Breaking Changes

1. Terraform Enterprise disables public self-registration by default with the `enable-public-registration` setting. Instances that relied on public self-registration before this release have unauthenticated sign-ups silently blocked after upgrade until a site admin explicitly enables registration. To preserve open-registration behavior, set `enable-public-registration` to `true` with the [Admin Settings API](/terraform/enterprise/api-docs/admin/settings#update-general-settings), or enable **Enable public registration** in [**Admin** > **Settings**](/terraform/enterprise/application-administration/general#public-registration).

## Deprecations

1. In a future release, Terraform Enterprise will be transitioning to Red Hat Universal Base Image (UBI) as its base operating system. If you have built a custom Terraform Enterprise image on top of the current base image, you will need to rebuild your image and update any OS-specific customizations for compatibility. Note that IBM does not recommend building custom Terraform Enterprise images — running the official, unmodified image is the supported deployment path. If you have specific requirements that led you to create a custom image, contact your IBM account representative.
1. The `idp-cert` and `old-idp-cert` attributes in the `admin/saml-settings` endpoint, and the `admin/saml-settings/actions/revoke-old-certificate` action, are deprecated and will be removed in a future release. This is part of the transition to multiple SAML IdP certificates. Use the [SAML IdP Certificates API](/terraform/enterprise/api-docs/admin/saml-idp-certificates) instead.

## Highlights

1. Terraform Enterprise now supports Redis 8.0 and Valkey 9.0 for the required external cache. Valkey is a drop-in replacement for Redis and uses the same connection settings.
1. You can now deploy Terraform Enterprise to IBM Cloud giving you additional flexibility when hosting Terraform Enterprise in your cloud environment. You can also use the [Terraform Enterprise on IBM Cloud deployable architecture](https://cloud.ibm.com/catalog/7a4d68b4-cf8b-40cd-a3d1-f49aff526eb3/architecture/deploy-arch-ibm-terraform-enterprise-42170cf3-6337-453e-8d2d-ffabd48c4914-global) to automate deployment with supporting IBM Cloud services.
2. The admin console now supports flexible access modes through the new `TFE_ADMIN_CONSOLE_ACCESS_MODE` configuration setting.
3. Redis mTLS connections now support password authentication. Both can be enabled at the same time - certificate-based mutual TLS and Redis ACL credentials.
4. Terraform Enterprise introduces a Node Drain Status API that lets you check whether a node is safe to terminate before removing it from a deployment. Use these endpoints to avoid interrupting active Terraform runs during node maintenance or scaling operations.
5. Terraform Enterprise now provisions the read-only Site Auditor role automatically through your identity provider. Configure a SAML attribute or role, or map a SCIM group, to grant and revoke cross-organization Site Auditor access without manual admin action. When SCIM is enabled, SAML auditor provisioning is skipped. The role is Terraform Enterprise only and cannot be granted to service accounts. Refer to the SAML and SCIM configuration guides for details.
6. You can now modify specific configuration values on a running Terraform Enterprise node without restarting it. Refer to [Modify node configuration](/terraform/enterprise/application-administration/config-reload) for more information.
7. Terraform Enterprise now supports the Cloudability native task integration (public beta). The Cloudability native task enables cost estimation, FinOps policy evaluation, and optimization recommendations as part of your infrastructure automation workflow, without requiring users to leave Terraform. This integration requires tfc-agent version 1.31.1 or later, and your instance must be able to reach Cloudability endpoints for your region.
8. Terraform Enterprise now trusts multiple SAML IdP certificates at the same time. Refer to [Manage IdP certificates](/terraform/enterprise/saml/configuration#manage-idp-certificates) for more information.
9. You can now configure site-wide banners in Terraform Enterprise to broadcast messages to all users, and customize key UI links to point to internal support channels relevant to your company.
10. Terraform Enterprise sends notification emails at 30 days and seven days before a user, team, audit, or organization token expires. The expiration window is intended to give you sufficient time to rotate or renew tokens before they expire.
11. The Team Tokens page now supports improved filtering by token expiration status and bulk deletion, making it easier to find and manage multiple tokens.


## Features

### Multiple SAML IdP certificates

Terraform Enterprise previously trusted exactly one active SAML IdP certificate, plus one temporary certificate during a rotation window. Terraform Enterprise now stores IdP certificates as a collection and verifies each SAML response against every trusted certificate, so an identity provider that signs with different certificates per region no longer breaks logins during a failover.

Each certificate is a separate resource with its own identifier, display name, fingerprint, issuer, and expiration date. Manage certificates from **Site Admin > SAML**, or with the new [SAML IdP Certificates API](/terraform/enterprise/api-docs/admin/saml-idp-certificates).

Rotation is now "add the new certificate, confirm logins, then delete the old one." Terraform Enterprise prevents you from deleting the last trusted certificate while SAML is enabled, rejects certificates that it cannot parse, that have expired, or that it already trusts, and records an audit log entry for every certificate change.

Terraform Enterprise migrates existing `idp-cert` and `old-idp-cert` values into the new collection automatically. The existing `admin/saml-settings` attributes and the `revoke-old-certificate` action continue to behave as before, but are deprecated.

Refer to [Manage IdP certificates](/terraform/enterprise/saml/configuration#manage-idp-certificates) for more information.

### Admin console access modes

Terraform Enterprise 2.1.0 introduces the `TFE_ADMIN_CONSOLE_ACCESS_MODE` environment variable, which provides flexible options for accessing the admin console:

- `port` (default): Admin console accessible only via dedicated port (e.g., `:8443`)
- `path`: Admin console accessible only via standard HTTPS path (`/platform/admin`)
- `both`: Admin console accessible via both dedicated port and standard HTTPS path

By default, the admin console remains accessible only through the dedicated port, maintaining backward compatibility with existing deployments.

**Security consideration for `both` mode:** When set to `both`, the admin console becomes accessible on port `:443`, which is already open for standard TFE traffic. This bypasses network-level blocking of the dedicated admin console port. To restrict access when using `both` mode, implement path-level IP allow-listing at your reverse proxy or load balancer.

Refer to [Access the admin console](/terraform/enterprise/deploy/manage/access-admin-console) for additional information.

## Improvements

1. Terraform Enterprise now uses agent-based VCS ingress, which packages version control data in an agent job rather than through the standalone `slug-ingress` service. Ingress jobs run on demand alongside your other agent workloads and do not count against an organization's run concurrency. Configuration versions, policy set versions, and registry module versions continue to ingress as before, with no change to the Terraform Enterprise UI or API. Terraform Enterprise still ships and runs the `slug-ingress` service as a fallback, so upgrading requires no configuration change. On Kubernetes, agent-based VCS ingress creates additional agent pods in your agents namespace.
1. The Azure object storage configuration now supports block size and concurrency parameters, which brings it closer to parity with the AWS object storage configuration.
1. Site administrators can now disable outbound requests to gravatar.com by configuring Terraform Enterprise to display a default avatar icon instead, improving privacy and compatibility with restricted network environments.
