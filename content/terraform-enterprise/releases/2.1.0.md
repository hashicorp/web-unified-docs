## Deprecations

1. Relying on implicit auto-detection of Azure Workload Identity for object storage is deprecated. In future deployments, explicitly set `TFE_OBJECT_STORAGE_AZURE_USE_WORKLOAD_IDENTITY` to `true` or `false` rather than depending on auto-detection based on the `AZURE_FEDERATED_TOKEN_FILE` environment variable. Refer to [Deploy to Kubernetes](/terraform/enterprise/deploy/kubernetes#using-aks-with-workload-identity) for details.

## Features

1. Terraform Enterprise now provides documented workload identity support for all three major cloud-managed Kubernetes platforms: AWS EKS (via IRSA and EKS Pod Identity), GCP GKE (via Workload Identity Federation), and Azure AKS (via Workload Identity). Workload identity eliminates the need for static credentials such as access keys, service account JSON files, and storage account keys when authenticating to object storage, database, and Redis services. Refer to [Deploy to Kubernetes](/terraform/enterprise/deploy/kubernetes#example-configurations) for supported configurations, prerequisites, and limitations.
1. Terraform Enterprise introduces a new `TFE_OBJECT_STORAGE_AZURE_USE_WORKLOAD_IDENTITY` environment variable that lets you explicitly control whether object storage authenticates with Azure Workload Identity on AKS. Set it to `true` to enable workload identity for object storage, or `false` to use a storage account key for object storage even when workload identity is active on the pod for other services such as PostgreSQL and Redis. When the variable is not set, Terraform Enterprise auto-detects workload identity based on the presence of the `AZURE_FEDERATED_TOKEN_FILE` environment variable injected by the AKS workload identity webhook. Refer to [Deploy to Kubernetes](/terraform/enterprise/deploy/kubernetes#using-aks-with-workload-identity) for details.
