# Terraform policy evaluations API reference

[Terraform policy](/terraform/policy) evaluations evaluate policy sets during workspace runs. Each evaluation belongs to a run and an `Init` (Setup), `Plan`, or `Apply` stage. Use these endpoints to list evaluations, inspect policy set outcomes, and override eligible failures.

These endpoints are separate from the [policy evaluations API for Sentinel and OPA](/terraform/enterprise/api-docs/policy-evaluations), which associates evaluations with task stages.

All endpoint paths are relative to `https://tfe.example.com/api/v2`. In the sample requests, replace `tfe.example.com` with your Terraform Enterprise hostname.

## Evaluation attributes

Evaluation resources have the JSON API type `tf-policy-evaluations`.

| Attribute | Type | Description |
| --------- | ---- | ----------- |
| `status` | string | The [evaluation status](#evaluation-statuses). |
| `stage-type` | string | The evaluation stage: `Init` (Setup), `Plan`, or `Apply`. |
| `status-timestamps` | object | Transition timestamps, such as `running-at`, `passed-at`, and `awaiting-override-at`. |
| `created-at` | string | When Terraform Enterprise created the evaluation, in ISO 8601 format. |
| `updated-at` | string | When Terraform Enterprise last updated the evaluation, in ISO 8601 format. |
| `result-count` | object | Aggregated policy counts: `advisory-failed`, `mandatory-failed`, `mandatory-overridable-failed`, `passed`, `errored`, and `unknown`. |
| `error` | object or null | Evaluation-level error information with `type`, `summary`, and `detail`. Error types include `setup_error`, `tool_version_error`, `incompatible_agent_version`, and `incompatible_terraform_version_error`. |
| `archivist-supported` | boolean | Returns `true`. Retrieve full policy results using each outcome's `policy-set-result-url`. |
| `permissions.can-override` | boolean | Whether the authenticated user has permission to override the failed evaluation. |
| `actions.is-overridable` | boolean | Whether the authenticated user can override the evaluation in its current stage and state. |

The `run` relationship identifies the parent run. The `tf-policy-set-outcomes` relationship links to the evaluation's policy set outcomes.

### Evaluation statuses

The evaluation status is separate from the parent [run state](/terraform/enterprise/api-docs/run#run-states).

| Status | Description |
| ------ | ----------- |
| `pending` | The evaluation has not entered the queue. |
| `queued` | The evaluation is waiting to start. |
| `running` | The evaluation is in progress. |
| `awaiting_override` | Policies with `mandatory_overridable` enforcement failed and the evaluation is awaiting an override. |
| `passed` | The evaluation passed. Advisory failures do not block a run. This is a final state. |
| `failed` | Policies with mandatory enforcement failed. This is a final state. |
| `overridden` | An authorized user overrode the evaluation. This is a final state. |
| `errored` | An error prevented the evaluation from completing successfully. This is a final state. |
| `canceled` | The evaluation was canceled. This is a final state. |
| `unreachable` | The evaluation remained pending when the run reached a final state. |

## List Terraform policy evaluations for a run

`GET /runs/:run_id/tf-policy-evaluations`

This endpoint lists the Terraform policy evaluations associated with a run.

| Parameter | Description |
| --------- | ----------- |
| `:run_id` | The ID of the run to list evaluations for. |

The endpoint returns the following responses.

| Status | Response | Reason |
| ------ | -------- | ------ |
| [200][] | [JSON API document][] | Success. |
| [404][] | [JSON API error object][] | Run not found or access not authorized. |

### Query parameters

This endpoint supports [pagination](/terraform/enterprise/api-docs#query-parameters).

| Parameter | Description |
| --------- | ----------- |
| `page[number]` | **Optional.** The page to return. Defaults to the first page. |
| `page[size]` | **Optional.** The number of evaluations per page. Defaults to `20`. |

### Sample request

The following request lists evaluations for a run.

```shell
curl \
  --header "Authorization: Bearer TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  --request GET \
  https://tfe.example.com/api/v2/runs/run-CZcmD7eagjhyX0vN/tf-policy-evaluations
```

## Show a Terraform policy evaluation

`GET /tf-policy-evaluations/:id`

This endpoint returns details about a specific evaluation.

| Parameter | Description |
| --------- | ----------- |
| `:id` | The evaluation ID, which begins with `tfpeval-`. |

The endpoint returns the following responses.

| Status | Response | Reason |
| ------ | -------- | ------ |
| [200][] | [JSON API document][] | Success. |
| [404][] | [JSON API error object][] | Evaluation not found or access not authorized. |

### Query parameters

Use the `include` parameter to request related resources.

| Parameter | Description |
| --------- | ----------- |
| `include` | **Optional.** Set to `tf_policy_set_outcomes` to include policy set outcome resources in the top-level `included` array. |

### Sample request

The following request retrieves an evaluation.

```shell
curl \
  --header "Authorization: Bearer TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  --request GET \
  https://tfe.example.com/api/v2/tf-policy-evaluations/tfpeval-8Jj9Hfoz892D9WMX
```

### Sample response

## Override a Terraform policy evaluation

`POST /tf-policy-evaluations/:id/actions/override`

This endpoint overrides an eligible evaluation so the run can continue. The following requirements apply:
- **Evaluation status:** The evaluation must have the `awaiting_override` status.
- **Policy enforcement:** You can override failures for policies with the `mandatory_overridable` enforcement level. You cannot override an evaluation if any policy with the `mandatory` enforcement level failed. Refer to [Terraform policy enforcement levels](/terraform/policy#enforcement-levels) for more information.

Only plan-stage evaluations for runs that are not plan-only support overrides. When the associated run is paused in `tf_policy_override`, overriding the evaluation allows the run to continue.

You need [manage policy overrides](/terraform/enterprise/users-teams-organizations/permissions/organization#manage-policy-overrides) permissions to override failed Terraform policy evaluations. Check `permissions.can-override` and `actions.is-overridable` before submitting an override.

| Parameter | Description |
| --------- | ----------- |
| `:id` | The ID of the evaluation to override. |

The endpoint returns the following responses.

| Status | Response | Reason |
| ------ | -------- | ------ |
| [200][] | [JSON API document][] | The evaluation was overridden. |
| [404][] | [JSON API error object][] | Evaluation not found or access not authorized. |
| [409][] | [JSON API error object][] | The evaluation is not in an overridable state. |

### Request body

The request body is optional. Supply the comment as a top-level property, not inside a JSON API `data` object.

| Property | Type | Description |
| -------- | ---- | ----------- |
| `comment` | string or null | **Optional.** The reason for overriding the evaluation. |

### Sample request

The following request overrides an evaluation and records a comment.

```shell
curl \
  --header "Authorization: Bearer TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  --request POST \
  --data '{"comment":"Approved exception for this run."}' \
  https://tfe.example.com/api/v2/tf-policy-evaluations/tfpeval-8Jj9Hfoz892D9WMX/actions/override
```

### Sample response

The following response excerpt shows the updated evaluation. Overriding an evaluation does not change its failed policy result counts.

```json
{
  "data": {
    "id": "tfpeval-8Jj9Hfoz892D9WMX",
    "type": "tf-policy-evaluations",
    "attributes": {
      "status": "overridden",
      "stage-type": "Plan",
      "status-timestamps": {
        "awaiting-override-at": "2026-09-01T10:00:10Z",
        "overridden-at": "2026-09-01T10:05:00Z"
      },
      "permissions": {
        "can-override": false
      },
      "actions": {
        "is-overridable": false
      }
    }
  }
}
```

## List Terraform policy set outcomes

`GET /tf-policy-evaluations/:tf_policy_evaluation_id/tf-policy-set-outcomes`

This endpoint lists policy set outcomes for an evaluation.

| Parameter | Description |
| --------- | ----------- |
| `:tf_policy_evaluation_id` | The ID of the evaluation that contains the outcomes. |

The endpoint returns the following responses.

| Status | Response | Reason |
| ------ | -------- | ------ |
| [200][] | [JSON API document][] | Success. |
| [400][] | [JSON API error object][] | Invalid filter. |
| [404][] | [JSON API error object][] | Evaluation not found or access not authorized. |

### Query parameters

This endpoint supports [pagination](/terraform/enterprise/api-docs#query-parameters) and outcome filters. Percent-encode `[` as `%5B` and `]` as `%5D` if your tooling does not encode them.

| Parameter | Description |
| --------- | ----------- |
| `page[number]` | **Optional.** The page to return. Defaults to the first page. |
| `page[size]` | **Optional.** The number of policy set outcomes per page. Defaults to `20`. |
| `filter[n][status]` | **Optional.** Filter by `passed`, `failed`, `errored`, or `unknown`. |
| `filter[n][enforcement_level]` | **Optional.** Filter by `advisory`, `mandatory`, or `mandatory_overridable`. |

Each numeric index defines a group. Conditions in the same group use AND; different groups use OR. Filters select policy sets containing matching policy outcomes. They do not remove individual policy results from a matching policy set.

Use `enforcement_level` for these endpoints, not the `enforcementLevel` parameter used by the Sentinel and OPA policy evaluations API.

### Sample request

The following request returns policy set outcomes containing an errored policy or a failed policy with `mandatory_overridable` enforcement. The `--globoff` option prevents curl from interpreting square brackets as URL patterns.

```shell
curl --globoff \
  --header "Authorization: Bearer TOKEN" \
  --header "Content-Type: application/vnd.api+json" \
  --request GET \
  "https://tfe.example.com/api/v2/tf-policy-evaluations/tfpeval-8Jj9Hfoz892D9WMX/tf-policy-set-outcomes?filter[0][status]=errored&filter[1][status]=failed&filter[1][enforcement_level]=mandatory_overridable"
```

### Sample response

### Retrieve full policy results

Policy set outcome resources have the JSON API type `tf-policy-set-outcomes`. The `result-count` attribute summarizes policy results, while full results contain policy diagnostics and resource details.

| Attribute | Type | Description |
| --------- | ---- | ----------- |
| `policy-set-name` | string | The name of the evaluated policy set. |
| `policy-set-description` | string or null | The policy set description. |
| `result-count` | object | Counts for `advisory-failed`, `mandatory-failed`, `mandatory-overridable-failed`, `passed`, `errored`, and `unknown`. |
| `policy-set-result-url` | string or null | A URL to download full policy results. |
| `outcomes` | array or null | **Deprecated.** Use `policy-set-result-url` to retrieve full policy results. |
| `error` | string or null | **Deprecated.** Policy set error information. |
| `overridable` | boolean | **Deprecated.** Do not use this field to determine whether you can override an evaluation. Use the parent evaluation's `permissions` and `actions` instead. |

To retrieve full results:

1. Retrieve the [policy set outcome](#show-a-terraform-policy-set-outcome).
1. Download the full policy results from its `policy-set-result-url`.

Download URLs expire after 30 minutes. Retrieve the outcome again to obtain a fresh URL.

If `policy-set-result-url` is `null`, no result download is available. Check the parent evaluation's `status` and `error` attributes rather than interpreting a missing URL as a successful evaluation.

#### Downloaded policy results

The downloaded content is a JSON array of policy outcomes for one policy set. Each entry describes a policy's enforcement level, result, diagnostics, and resources. Field names use underscores, such as `policy_name` and `enforcement_level`.

Each array entry contains the following fields.

| Field | Type | Description |
| ----- | ---- | ----------- |
| `policy_name` | string | The name of the evaluated policy. |
| `enforcement_level` | string | The policy's enforcement level: `advisory`, `mandatory`, or `mandatory_overridable`. |
| `status` | string | The policy result: `passed`, `failed`, `errored`, or `unknown`. |
| `file_name` | string | The policy file name. |
| `diagnostics` | array | **Optional.** Diagnostic details grouped by enforce block. Empty diagnostic arrays are omitted. |
| `passed_resources` | array | **Optional.** Resources that passed all enforce blocks for the policy. Empty arrays are omitted. |

Diagnostic entries can include `code`, `context`, `start_line`, and `summary` to identify the policy code and explain the result. When there are no resource diagnostics, the error message appears directly on the diagnostic entry as `error_message`, and the `resources` array is omitted. Otherwise, the `resources` array contains resource-specific details:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `resource_name` | string | The Terraform resource address. |
| `error_message` | string | The resource-specific error or failure message. |
| `info_message` | string | An informational message from the policy. |
| `code` | string | A code excerpt from the Terraform configuration. |
| `file_name` | string | The Terraform configuration file name. |
| `start_line` | integer | The starting line of the configuration excerpt. |
| `values` | array | Attribute details. Each entry contains a `traversal` identifying the attribute and a `statement` describing its value. |

Resource diagnostic fields are omitted when they have no value. Entries in `passed_resources` contain a `resource_name` and, when present, an `info_messages` array.

The download does not include aggregate counts. Use the policy set outcome API resource's `result-count` for totals. These totals count policies, not resources: a failed policy can contain both resource diagnostics and resources that passed.
